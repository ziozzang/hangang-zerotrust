# hangang-world Helm chart

[한국어](README.ko.md) · [Install guide](../../docs/HELM_INSTALL.md) · [ADR 0022](../../docs/adr/0022-kubernetes-native-world-package.md)

One release installs the four Hangang World components as an integrated zero-trust package:

| Component | Role | Workload | Ports (Service) |
| --- | --- | --- | --- |
| Hangang | Ingress controller and enforcement gateway; compiles `ProtectionPolicy` into routes | Deployment, stateless, N replicas | public `http`/`https`, optional `admin` 9000 (TLS, metrics) |
| Hopae | Identity, sessions, native gateway verification | Deployment, single SQLite replica (PostgreSQL once Hopae ships it) | `portal` 8700, `grpc` 8703 (mTLS) |
| Pumgye | Authorization decisions | Deployment, single writer (SQLite) | `management` 9084, `ppg1` 9085, `grpc` 9087 (mTLS) |
| Sumunjang | Network admission (IP/risk) | Deployment, single writer (SQLite) | `management` 9080, `binary-mtls` 9081, `grpc-mtls` 9082 |

The CRDs (`world.hangang.dev`) and the aggregated `world-admin`/`world-editor`/`world-viewer` roles ship in the separate [`hangang-world-crds`](../hangang-world-crds) chart. Install it first, with the same version.

## What the chart guarantees

- **Strict values.** `values.schema.json` rejects unknown keys, malformed CIDRs, names and durations, and states that cannot work (cross-field rules live in `templates/validate.yaml`). The schema is generated by `tools/helm/build_world_schema.py`.
- **Digest-pinned images.** Every enabled component needs `image.digest` (`sha256:…`); tags are informational only.
- **Hardened Pods.** UID/GID 65532, `runAsNonRoot`, `readOnlyRootFilesystem`, `allowPrivilegeEscalation: false`, all capabilities dropped, `RuntimeDefault` seccomp, no service links, ServiceAccount tokens mounted only into Hangang (the only component that calls the Kubernetes API).
- **No secret values in values.** API credentials, PostgreSQL URLs and provider secrets are referenced from Secrets you create; the chart never renders a `Secret`.
- **Mutual TLS everywhere.** One certificate per component (server and client authentication) with its Service DNS names and SPIFFE ID `spiffe://<trustDomain>/ns/<namespace>/sa/<serviceAccount>`, issued by cert-manager (bootstrap private CA or your Issuer/ClusterIssuer), or bring-your-own Secrets.
- **Least-privilege RBAC.** Hangang gets `get/list/watch` on Services, Ingresses and ProtectionPolicies, `patch` on `protectionpolicies/status`; Secrets only with `kubernetesTls`, `ingresses/status` only with `publishAddress`; a namespaced Role unless `watchScope: Cluster`.
- **NetworkPolicies.** Default-deny ingress for every World Pod, then only the calls the architecture makes: anyone (or `networkPolicy.publicFrom`) → Hangang; Hangang → Hopae, Pumgye, Sumunjang; Pumgye → Sumunjang; metrics peers → Hangang admin.
- **Fail-closed protection.** With `hangang.protection.enabled` the gateway withholds Ingresses without an effective `ProtectionPolicy`, and Sumunjang admission runs in per-request query mode that denies on failure.
- **Client address preservation** for network-conditioned policies: `serviceLocal` (`externalTrafficPolicy: Local`), `proxyProtocol` (PROXY v2 from trusted CIDRs only), `hostNetwork`, or `none` (such policies are then withheld).
- **Availability.** Rolling updates with `maxUnavailable: 0` for stateless components, `Recreate` for single writers, topology spread for the gateway, PodDisruptionBudgets whenever a component runs more than one replica, readiness tied to controller authority.
- **State you keep.** PVCs carry `helm.sh/resource-policy: keep`; `existingClaim` adopts restored volumes.
- **Operations.** Optional `ServiceMonitor` (HTTPS, bearer token from your Secret), `helm test` connectivity checks, and `NOTES.txt` that warns about missing CRDs or client address preservation.

## Scaling and HA

Hangang is stateless in controller mode and scales freely. Hopae stays a single SQLite replica: its PostgreSQL store is not released yet (Hopae 0.0.10 refuses `store.url_env`), so the chart refuses `storage.backend: postgresql`. Pumgye and Sumunjang are single writers in this release (`replicas` is capped at 1 by the schema); ADR 0022 makes them stateless snapshot replicas once signed snapshot distribution exists. The chart refuses `replicas > 1` on SQLite rather than letting two Pods share one database.

## Upgrades and rollback

Upgrade `hangang-world-crds` first, then `hangang-world` of the same version. Supported: N-1 → N and `helm rollback` to N-1 within a minor series; see the [install guide](../../docs/HELM_INSTALL.md#upgrade-and-rollback) for the backup and order rules.
