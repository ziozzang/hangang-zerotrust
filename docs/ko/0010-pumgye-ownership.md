# ADR 0010: 품계 권한 관리와 컴포넌트 소유권

상태: 설계 확정. 런타임 구현·검증은 진행 예정.

## 결정

품계(Pumgye)는 결정적 권한 관리자다. 호패는 신원·프로바이더·사용자·세션을,
수문장(Sumunjang, 기존 Guard)은 네트워크 접근과 IP 위험 근거를 소유한다.
Hangang은 통합 판단을 집행하고 관리 화면을 제공한다.

품계가 서비스별 역할·권한·정보등급과 사용자/IP 권한 매트릭스를 소유한다.
컴파일된 코어는 Hangang에 내장하고, Hangang의 리비전 기반 설정 권한으로
정책을 게시한다. 호패나 수문장의 사용자 DB를 공동 쓰기하지 않는다.

로그인해도 서비스 배정이 없는 사용자는 guest이며 권한이 없다. 요청 권한과
정보등급은 사용자 배정과 신뢰할 수 있는 소스 네트워크 배정 모두를 충족해야 한다.
IP 권한으로 사용자 권한을 올릴 수 없다. 네트워크는 최장 프리픽스로 선택하며,
더 구체적인 guest 배정이 넓은 허용 대역보다 우선한다. 근거 누락, 미등록
서비스·행위·등급, 잘못된 정책은 거부한다. 수문장의 차단이 항상 우선한다.
수문장 집행을 요구하는 게이트는 observe·근거 불가·fail-open을 허용 근거로 쓰지 않는다.

서비스·행위·등급은 보호 라우트 정책에서, 신원은 호패의 인증된 검증에서,
IP는 Hangang의 신뢰된 전송/엣지 컨텍스트에서 얻는다. 브라우저·Lua·원본 서버의
헤더가 이 근거를 만들 수 없다. 인증 성공만으로 접근 권한을 부여하지 않는다.

## 구현 절차

1. 크기 제한이 있는 Rust 정책 컴파일러와 불변 평가기를 구현한다. 참조·역할
   상속·등급·문서 크기를 게시 전에 검증한다.
2. Hangang 네이티브 설정·CAS·감사·관리자 권한과 통합하고 서비스/사용자/IP
   매트릭스를 콘솔에 추가한다.
3. 보호 리소스 네임스페이스에 집행을 연결한다. 경로 정규화·보호 해제·헤더
   격리·철회 방어를 유지하고 캐시 응답 전에 권한을 판단한다. 철회된 스트림도 종료한다.
4. guest 거부, 서비스 격리, 읽기/쓰기, 정보등급, IPv4/IPv6 세부 대역 우선,
   오래된 정책, 네트워크 장애/차단, 헤더 위조, 관리자/조회자 격리를 검증한다.
5. 검토·머지·배포 후 실제 HTTP/네이티브 경로와 브라우저를 검증한다.
   코어 벤치마크만으로 종단간 10만 QPS를 주장하지 않는다.

기존 인증 전용 라우트와 새 품계 보호 라우트를 명시적으로 구분한다. 배포만으로
광범위한 운영 권한이나 차단을 만들지 않는다. 수문장 명칭 전환 중 기존 Guard
식별자·프로토콜·릴리즈 이름·자동업데이트 URL 호환성을 유지한다.

## 관측 컴포넌트: 설계 범위

장부(Jangbu)는 ClickHouse와 제한된 exporter를 사용하는 별도 로그·트레이스
수집/저장/검색 모듈이다. 메트릭은 Prometheus와 연결한다. 사헌(Saheon)은 별도 감사 시스템으로
권한 변경·접근 판단·관리자 행위와 무결성/검증 조회를 맡는다. 도메인 권한은
변경을 원자적으로 기록하고 사헌에 제한된 감사 근거를 전달한다. 사헌에 정책 쓰기
권한을 주거나 요청 경로에 분석 저장을 동기적으로 연결하지 않는다. 이미 존재하는
사초(Sacho)는 모니터링·상태·알림을 맡으며 로그 저장 모듈로 간주하거나 재구현하지 않는다.
실록(Sillok)은 근거를 사실·관계·출처로 구성한다. 직지는 허가된 범위 또는 검토를
통과한 조치를 실행하고 헤아림을 판단 보조로 사용한다. 적용 상태와 검증 결과를
장부에서 실록으로 되돌린다. 이 컴포넌트는 품계 권한을 부여하지 않으며 요청 경로가
분석 저장을 동기적으로 기다리지 않는다. 해당 통합은 설계 단계로 유지한다.
