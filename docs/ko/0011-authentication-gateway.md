# ADR 0011: 인증 게이트웨이로서의 호패

상태: 방향 확정. 커넥터·결합 런타임 구현은 진행 예정.

호패는 사람·서비스·워크로드·외부 신원의 인증 게이트웨이다. 여러 Google/OIDC
발급자, LDAP 디렉터리, API 인증 릴레이와 네트워크 근거를 함께 구성해야 한다.
현재 레지스트리는 여러 OIDC 프로바이더를 지원하지만 LDAP·API 릴레이·네트워크
결합은 아직 구현되지 않았다. enum에 이름이 있는 것만으로 구현을 주장하지 않는다.

커넥터는 프로토콜을 검증하고 프로바이더/발급자·주체·주체 종류·realm·검증 방법·
유효 시간·인증 수준의 의미·출처를 보존한다. 호패는 검증 근거를 제한된 결과로
결합한다. 수문장은 IP/CIDR/네트워크 접근·위험 근거를 제공하고, 소스 IP는 Hangang의
신뢰된 전송 컨텍스트에서 얻는다. 네트워크도 인증 입력이다. 품계는 서비스 권한과
정보등급을, Hangang은 최종 요청 집행을 소유한다.

외부 주체는 발급자/프로바이더와 realm으로 구분한다. 이메일·이름 일치만으로
자동 병합하지 않는다. 검증된 권한과 명시적 정책/승인된 연결 절차가 필요하다.
기계 자격 증명에 사람 MFA 수준을 임의로 부여하지 않는다. 명시된 네트워크 주체로
네트워크 전용 인증을 구성할 수 있지만 사람의 신원이나 무제한 내부 권한을
의미하지 않는다. 서비스가 수용할 주체/근거 종류를 선언하고 기본은 guest/권한 없음이다.

any·all·step-up 체인은 커넥터 ID, 자격 증명 입력과 시간 제한을 명시한다.
LDAP와 필수 네트워크, Google 또는 외부 OIDC, API 자격 증명과 네트워크 집행을
결합할 수 있어야 한다. 필수 검증 실패를 숨기는 묵시적 fallback은 허용하지 않는다.
다른 주체·발급자·realm의 근거 충돌은 미리 검증된 관계가 없으면 거부한다.
누락·오래된 증명·부분 장애가 허용으로 바뀌지 않도록 철회·감사·출처를 유지한다.

기존 브라우저 begin/complete 트레이트만으로 LDAP bind·API 릴레이·네트워크를
표현하지 않는다. 공통 커넥터/근거 계약과 브라우저·직접 자격 증명 어댑터를 추가하고
기존 OIDC 트랜잭션·nonce·PKCE·세션 방어를 유지한다.

API 릴레이는 운영자가 고정한 검증 엔드포인트·입력 형식·claims 매핑·발급자·대상
앱으로 제한한다. 인증 API·bearer introspection·디렉터리 검증 후 대상 전용 자격
증명을 변환/주입할 수 있다. 호출자가 임의 목적지를 고르거나 자격 증명을 다른
백엔드로 복사하지 못하게 한다. TLS·redirect·응답·동시성·시간을 제한하고 비밀을
노출하지 않는다. 입력 자격 증명, 검증 신원, 출력 자격 증명을 구분한다. 허가된
업스트림 요청에만 전달하며 브라우저·캐시·로그·트레이스·온톨로지에 비밀을 남기지 않는다.

구현 순서는 근거/주체 계약 → 기존 다중 OIDC 어댑터 → API/LDAP → 네트워크와
결합 → HOP1/HTTP 및 품계 주체 종류 집행 → 통합 관리자 화면 → 혼합 신원·충돌·
부분 장애·철회·주입·자격 증명 격리·네이티브 동등성·성능 검증 → 머지/릴리즈/배포다.
관측·온톨로지·감사 모듈은 별도 설계 범위를 유지하며 모델이 인증 근거나 권한을 만들지 않는다.

## 전체 수명주기와 네이티브 auth-proxy

호패는 Hangang 스택의 네이티브 인증 서브시스템이다. 요청·신뢰 전송 컨텍스트·
설정 권한·콘솔을 재사용하며 프로바이더 로직은 호패 소유로 유지한다. 입력 추출 →
호패 검증/결합 → 품계 권한 판단 → 서비스 전용 자격 증명 생성 → 허가된 업스트림
요청 순서로 집행한다.

외부 인증과 자체 인증 모두 공통 커넥터 계약을 사용한다. 입력 프로토콜과 출력
어댑터를 분리하고 서비스별 헤더·Basic·Bearer/JWT·토큰 교환 등으로 변환한다.
확장 가능성과 실제 구현 완료를 구분한다. 비밀을 일반 템플릿 변수나 브라우저
출력으로 노출하지 않는다. 대상 서비스·audience·주체·정책 리비전에 묶고 권한
허용 후에만 전달한다.

로그인/로그아웃·추가 인증·세션·토큰 발급/변환/교체/만료/철회·관리자 비활성화·
감사를 담당한다. 커넥터와 출력 엔드포인트별 서킷 브레이커는 closed/open/half-open,
제한된 임계값·시간·동시성·복구 검증을 갖춘다. 일시 장애와 보안 격리는 구분하고
격리된 신뢰는 명시적 재승인이 필요하다. 필수 인증의 장애를 선언되지 않은 약한
인증으로 우회하지 않는다. 통합 관리 화면에 상태와 원인을 표시한다.

Independent runtime ownership is required by [ADR 0012](0012-independent-runtime.md).
