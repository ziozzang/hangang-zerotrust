# ADR 0013: 인메모리 authority 스냅샷과 스케일아웃 멤버십

상태: 필수 방향, fleet/DB 백본 구현은 진행 예정입니다.
[ADR 0012](0012-independent-runtime.md)를 확장합니다.
[English](../adr/0013-snapshot-membership-scaleout.md).

## 소유권과 메모리 모델

호패·수문장·품계는 독립 복제본 집합으로 배포합니다. 일반 검증·판단은 불변 컴파일된
메모리 스냅샷을 읽으며 DB 백본이 영속 상태와 게시를 소유합니다. 노드가 서로의 업무 DB를
독립적으로 덮어쓰지 않습니다. 호패의 신원·자격 증명·세션, 수문장의 네트워크 정책·근거,
품계의 역할·등급·매핑은 각 도메인에 유지합니다. DB 인프라는 공유할 수 있으나 스키마와
역할을 분리하며 사용자·네트워크·권한을 공유 multiwriter 모델로 합치지 않습니다.

품계의 로컬 서버는 이미 SQLite에서 정책·리비전·감사를 커밋하고 `ArcSwap` 컴파일 뷰를
교체합니다. HTTP/네이티브 판단은 DB를 읽지 않습니다. 분산 DB 어댑터나 멤버십 구독은
아직 구현되지 않았습니다. 수문장의 컴파일 네트워크 뷰는 기존 기반입니다. 호패는 검증
경로별 메모리 인덱스와 무효화를 추가해야 하며 현재 OIDC/세션 코드가 모든 인증 상태의
스냅샷 처리를 증명하지는 않습니다.

정책 스냅샷은 유효한 교체본 또는 authority lease 만료까지 유지합니다. 개별 판단 캐시는
1–5초로 제한하고 authority epoch·리비전·서비스·신원/근거·요청 범위를 묶습니다.
일반 경로에 비싼 DB·온톨로지·LLM·분석 작업을 두지 않습니다. 비공개 자격 증명은 보호된
도메인 저장소에 유지하며 API 키·비밀번호·프로바이더/세션 비밀값을 공개 스냅샷으로
전파하지 않습니다. 호패는 보호된 검증 인덱스와 세션/토큰별 회수 generation·tombstone이
필요하며 정책 스냅샷만으로 세션을 폐기할 수 없습니다.

## 영속 게시와 복제본 동기화

1. 도메인 게시 authority가 범위를 인증하고 제한된 CAS를 수행합니다.
2. DB 트랜잭션으로 상태·단조 증가 리비전·해시·감사 기록·change/outbox를 함께 커밋합니다.
3. 복제본은 watch 통지를 받고 인증된 원본을 조회해 epoch·리비전·해시·스키마를 검증하고,
   요청 executor 밖에서 컴파일한 뒤 원자적으로 교체합니다.
4. 교체 완료 후에만 적용 리비전을 승인합니다. DB 연결·heartbeat만으로 ready를 선언하지 않습니다.
5. 누락·overflow·알 수 없는 epoch·재연결은 원본 재동기화를 수행합니다. 통지는 힌트이며
   주기적 watermark 조회로 유실을 탐지합니다.

DB 백본은 배포를 고정하지 않는 어댑터로 둡니다. 로컬 단일 소유자 저장을 시작점으로,
PostgreSQL CAS·트랜잭션 outbox·인증된 snapshot/change 조회가 분산 어댑터 후보입니다.
전송·discovery 어댑터 변경이 업무 권한을 Hangang으로 옮기지 않습니다. 이 ADR은 실제
분산 DB 구현을 의미하지 않습니다. DB failover는 epoch·리비전 watermark를 유지해야 하고
복원·재초기화 시 fencing과 명시적 재승인이 필요합니다. 조용한 리비전 초기화는 금지합니다.

## 정책 리비전과 별도인 멤버십

범위가 있는 멤버십 authority가 generation과 제한된 lease를 제공합니다. 레코드는
도메인 authority/epoch·node ID/incarnation·endpoint/protocol·TLS 서비스 신원·용량·
준비 상태/컴파일 리비전·건강 상태·수명주기를 식별합니다. 멤버십 generation·정책 리비전·
노드 incarnation은 별개입니다. DNS 조회나 열린 소켓은 멤버십·준비 상태·권한 근거가 아닙니다.
[초안 스키마](../../schemas/membership.schema.json)와 [합성 예제](../../examples/membership.json)는
제한된 전체 뷰를 정의하며 서명된 실제 자격 증명이 아닙니다.

- 합류: 인증된 등록→초기 로드/동기화→컴파일→멤버십/도메인 lease 확보→필수 리비전 ready.
- 증설: 새 generation 게시→구독자 검증→범위·신원이 맞는 ready endpoint에만 제한된 풀 생성.
- 드레인/축소: 새 요청 할당 중단, 선택에서 제외, idle 연결 종료, 기한 내 진행 요청 드레인.
  신원·정책 회수는 정상 드레인 중에도 영향을 받는 작업을 종료합니다.
- 비정상 종료: heartbeat/lease 만료 시 제외합니다. 실패는 circuit을 열며 권한 우회가 아닙니다.
  대체 노드는 동일한 범위/epoch와 충분한 정책·회수 리비전을 가져야 합니다.
- 재시작: 새 incarnation으로 다시 동기화·준비 검증합니다. 기존 풀 세션이 새 incarnation에
  조용히 연결되지 않습니다.

멤버십 쓰기·watch는 인증된 범위별 authority가 담당합니다. 서비스 신원에 허용 도메인/
테넌트·endpoint 제약을 묶어 임의 인증 relay 목적지·평문 downgrade·관리자 자칭을 막습니다.
격리된 서비스 신원은 장애 복구와 별개로 명시적 재승인이 필요합니다.

## Hangang 의무

Hangang은 인증된 전체 멤버십 스냅샷과 제한된 watch 변경을 구독하고 단조 증가 generation을
유지하며 누락 시 재동기화합니다. authority별 제한된 풀을 유지하고 합류·드레인·제거에 따라
선택을 갱신합니다. 제외된 노드의 대기 작업을 취소하고 퇴역 풀로 새 호출을 보내지 않습니다.
TLS 신원·incarnation·네이티브 capability는 선택 레코드와 일치해야 합니다. 재시도에도
요청 ID·기한·최소 리비전·authority 범위를 보존합니다. 비멱등 credential exchange·로그인은
명시적 멱등 계약 없이 재실행하지 않습니다.

허용은 필수 리비전의 ready 노드가 제공한 신선한 도메인 근거에 의존합니다. 연결 핸드셰이크는
영구 권한 lease가 아닙니다. 처음에는 근거/회수 신선도 예산을 1초로 두고 서비스 정책이 허용할
때만 1–5초 안에서 조정합니다. 보호된 스트림·업로드는 제한된 재검증/만료 종료가 필요합니다.
세션/토큰 회수·네트워크 차단·품계 매핑/등급 변경의 도메인 리비전을 각각 추적합니다.
단일 평균 trust score나 heartbeat가 이 증명을 대체하지 않습니다.

제어 경로 분리 시 이미 검증된 스냅샷·근거의 유효 lease 안에서만 동작합니다. 필수 lease
만료나 리비전/epoch 미증명은 판단 불가로 차단합니다. deny는 보수적으로 유지할 수 있으나
판단 불가를 guest 허용·미선언 프로바이더 fallback으로 바꾸지 않습니다. 용량 변화는
스케줄링에만 영향을 주며 권한을 늘리지 않습니다.

통합 콘솔은 authority별 목표/적용 리비전·멤버 상태/age·lease 만료·incarnation·지연·
breaker·용량·드레인 진행을 표시해야 합니다. 관리는 소유 도메인 API에 CAS·감사를 위임합니다.
사초 모니터링·장부 영속 텔레메트리·사헌 감사 검증·실록 온톨로지는 이벤트를 관측하며
멤버십이나 정책의 쓰기 authority가 되지 않습니다.

## 통과 조건

- authority별 복제본 2개 이상과 Hangang을 실제 프로세스로 검증합니다.
- 초기 로드/동기화, watch 유실·중복·순서 역전, snapshot 변조, rollback/reset,
  오래된 복제본·회수된 서비스 인증서 거부를 검증합니다.
- 증설·축소, 동기화 전 ready 거부, 제한된 드레인, crash/restart, incarnation 불일치,
  DB/제어 경로 partition과 lease 만료를 검증합니다.
- 세션/토큰/계정 비활성화·IP 차단·역할/등급 회수가 정해진 기한 안에 전파되어야 하며
  열린 스트림과 인증 변환도 포함합니다.
- 재시도/failover의 네이티브/HTTP 일치와 서비스 credential 격리를 검증합니다.
- 실제 정책 규모·노드 증감·과부하/backpressure·p99/tail을 포함해 지속 10k/100k
  통합 판단 및 전체 요청 경로를 측정합니다.

품계 microbenchmark·멤버십 스키마·로컬 CAS 테스트만으로 fleet 보장을 주장할 수 없습니다.
어댑터와 Hangang 구독자를 구현·검증한 뒤 스케일아웃을 완료로 표시합니다.
