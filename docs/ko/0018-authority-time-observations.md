# ADR 0018 — 권한 소유자 기준 시간 관측

[English](../adr/0018-authority-time-observations.md)

상태: 초안. 공용 수치 코어는 구현했고 원천 측 관측 RPC 프로토타입은 개발 중입니다.
네이티브 클라이언트·permit·replay 연결은 미구현입니다. 네이티브 교차 호스트
receipt의 공개 릴리즈 gate입니다.
[Astra 검토 기록](2026-10-15-authority-time-review.md)을 참고합니다.

## 증거와 문제

서명된 0.3.6/0.0.8/0.1.7 정적 후보는 로컬 네 서버 검사를 통과했습니다.
격리 K8s 검사에서도 네 Pod를 거쳐 별도 원천 bearer가 전달됐지만 관리 컴퓨터의
독립 receipt 클라이언트는 거부됐습니다. 같은 고정 mTLS 소유자와 공개키를 사용한
진단에서 서명/범위는 유효하고 발급 시각이 로컬 수신보다 4ms 앞섰습니다. 엄격한
로컬 시간 검증이 거부했습니다. 발급 시각에서의 추가 서명 검사는 진단만을 위한
것이며 접근을 허용하거나 receipt/자격을 출력하지 않았습니다. 두 실행 모두 전체
검증은 실패이며 Pod 내부 성공 부분만으로 공개·운영 교체하지 않습니다.

서로 다른 시간 영역의 절대 밀리초를 같은 시계처럼 비교할 수 없습니다. 임의의
유예는 권한을 늘릴 수 있고 모든 요청의 대기는 고속 경로와 맞지 않습니다. 서명된
정규 시각과 소유자 시계 역행 보호를 유지하되 전송 근거를 명시적으로 모델링합니다.

## 제안 계약

인증된 고정 소유자는 자기 현재 시각과 제한된 잔여 수명을 정확한 요청/receipt
해시, 권한 목적/키/신원 epoch, 정확한 발급 시계 영역 신원, 캡처한 실제 소유자
세대에 결합해 보고합니다. 복제본이 공유하는 논리 발급자 별칭은 시계 영역이
아닙니다. 발급 영역에 라우팅하거나 명시적으로 인증된 변환을 사용해야 하며
follower의 벽시계로 조용히 대체할 수 없습니다.
자기 receipt·현재 상태·최종 guard를 검사한 뒤 보고해야 합니다. 잔여 수명은 양수,
최대 1,000ms이고 선행 관측이나 서명된 수명을 넘지 않습니다. 캐시 lease나 갱신이
아닙니다.

네이티브 클라이언트는 RPC 전후 절전을 포함하는 로컬 단조 시각을 캡처합니다. 비공개
관측은 정확한 불변 요청과 설정된 클라이언트 신원에 결합합니다. 요청이 고른 주소,
스크립트, 일반 인증 응답, 호출자가 제공한 allow/시간 값으로 생성할 수 없습니다.
mTLS/호출자 역할·상관관계·해시/세대 일치·크기/용량/기한·단조 시계 오류 검사를
통과해야 관측을 노출합니다. 관측 수신자의 집행과 replay 보존은 모두 같은 고정
원점 축을 사용합니다. 수신자 UTC는 입력이 아니므로 벽시계 이동이 만료나 정리를
움직이지 않습니다. 요청별 벽시계 연속성 잠금이나 epoch는 필요하지 않습니다.
기존 엄격 UTC 검증과 원천 소유 UTC 자격 예산은 별도로 유지합니다.

명시적인 동일 속도 시계 가정에서 소유자가 잔여 수명 R을 보고하면 로컬 구간으로
변환합니다.

- 가장 이른 만료: 로컬 RPC 시작 + R - 표본 불확실성 1ms. 최종 집행은 이 하한과 이미 수락한 모든
  기한·원래 수명 예산의 최솟값을 사용합니다.
- 가장 늦은 만료: 로컬 RPC 종료 + 소유자 시계에서의 전체 서명 receipt 잔여 수명 + 1ms. replay 행은 세대가 있는 영속 재시작 규칙과 함께
  적어도 이 상한까지 보존합니다. 집행 하한에 replay 행을 지우면 아직 유효한
  nonce를 다시 허용할 수 있습니다. 선행 관측이 짧아져도 원래 nonce 보존을 줄이지
  않습니다. 이후 질의에서 같은 서명 증명이 아직 수락될 수 있기 때문입니다.

독립 시계의 소수 tick 위상 때문에 집행은 한 tick 줄이고 보존은 한 tick 늘리는
바깥쪽 반올림이 필요합니다. 수락 유예가 아니며 양수 집행 구간이 없으면 거부합니다.

양자화는 시계 속도 오차를 제한하지 않습니다. 원천·수신자의 독립 오차 한계를
ppm 단위 `p_s`, `p_r`로 두고 모두 `10^6` 미만이어야 하며 검사된 유리수로 계산합니다.

- 집행 증가분: `floor((R_short - 1) * (10^6 - p_r) / (10^6 + p_s))`.
- 보존 증가분: `ceil(R_signed * (10^6 + p_r) / (10^6 - p_s)) + 1`.

네이티브 어댑터는 지원할 속도 모델을 검증해야 합니다. 집행만 줄이며 tombstone을
오래 보관하는 것은 수락 유예가 아닙니다. 임의 속도 오차, 원천 절전·복구나 원천의
계속된 진행을 증명하지 않습니다. Linux 수신자 기반은 호스트 절전을 포함하는
`CLOCK_BOOTTIME`을 사용하고 지원 불가·읽기 실패에서는 `Instant`로 우회하지 않습니다.
비동기 timeout이 아직 발생하지 않아도 최종 경계는 이 시계로 검사해야 합니다.
원천 시계와 원래 증명의 나이도 인증 대기 중 절전을 포함해야 하며 실제 적용은
아직 남아 있습니다.

요청별 SQL 읽기나 무제한 대기열을 추가하지 않고 경과 시간을 반영합니다. 과거
증명을 재사용하며 구간을 새로 시작하지 않습니다. 현재 상태가 필요하면 소유자에
다시 질의하고 새 결과도 기존 기한과 교집합을 취합니다. 피어 장애/비호환은 fallback
또는 정책 확대 없이 거부합니다.

## 구현·검토가 필요한 변경

- 발급/현재 검증 계약과 제한된 SDK에 명시적 시간 관측을 추가합니다. 기존 엄격한
  primitive를 유지하며 새 필드 누락을 조용히 재해석하지 않습니다.
- 암호학적 구조/서명/결합 근거와 시간 집행을 분리합니다. 서명 성공만으로 권한이나
  비밀을 만들 수 없습니다.
- 자기 서명 시각은 그 소유자 시간 영역에서 검증합니다. 인증/허가 결합은 인증된
  로컬 구간과 서명된 인증 해시를 사용하며 서로 다른 절대 시각을 계산하지 않습니다.
- 최종 출력 guard와 쌍 트랜잭션 replay 보존을 함께 수정합니다. 키/계획/프로필/앱/
  호출자 폐기와 취소 fence를 유지합니다.
- 시간 봉투 규칙은 정적 공용 라이브러리로 공유하고 상태·서버는 모듈별로 유지합니다.
  변경 가능한 권한 업무 스키마를 공유하지 않습니다.

## 필수 검증

양/음 원천 시계 차이, 변하는 RPC 지연, 원천 벽시계 역행, 수신자 벽시계 이동에도
만료·정리가 움직이지 않음, 절전, 속도 오차, 서명 만료 초과, 관측 누락/위조/
불일치, 세대 폐기, 요청/클라이언트 교체, 취소와 기존의 더 짧은 기한을 검사합니다.
권한 연장과 만료 하한/상한 사이 replay 공백이 없음을 입증합니다. 관리 컴퓨터의
독립 receipt 클라이언트와 실제 네 Pod 최종 전달, 브라우저/모듈 위임, 회수/재시작/
장애, 기존 모드 호환 검사를 수행합니다. 정확한 서명 자산을 다시 빌드·검증한 뒤
공개·배포합니다. fleet 복구와 초당 1만/10만 처리량은 별도의 미충족 gate입니다.

## 수치 코어 구현 증거

소스 `hopae-grpc::receipt_time`은 정확한 검증 receipt 해시·발급자 수명·제한된
로컬 표본·초과/만료·시계 불연속을 검사하고 집행을 교집합으로 제한하며 더 늦은
replay 상한을 유지합니다. SDK 21개가 통과했고 비대칭 지연 2,601개 및 소수 tick
위상/offset 405개 표본을 포함합니다. 보존은 짧아진 선행 보고가 아니라 전체
서명 잔여 수명을 사용합니다. 호출별 할당·SQL·네트워크 작업은 없습니다. 소수
tick 보정 후 전체 workspace 958개가 통과했고 기존 제외는 42개입니다. 엄격한
전체 대상 Clippy도 통과했습니다. 소스 기반은 호패 `7cd9c65`이며 고정된 초안
릴리즈 자산에는 아직 포함되지 않습니다.

이 helper는 수치 근거이며 인증된 관측이나 권한이 아닙니다. 이후 호패 소스는
명시적 원천 RPC·실제 소유자 guard·서명 전용 근거·독립 시계 속도 계산을 추가했습니다
(`cde8416`). 런타임 `ed2eee4`는 BOOTTIME 인스턴스 결합 기한·보존·경과 표본을
추가했습니다. 호패 `ce4d27f`는 공급자 인증 전 나이부터 절전을 포함한 원천·증명
예산을 적용했습니다. 호패 `2a96303`은 선택형 고정 원천 네이티브 클라이언트로
발급·외부 증명 최초 관측·이전 관측을 소비하는 갱신을 지원합니다. mTLS·호출자
메타데이터 인증, 정확한 원천 문맥 pin, 새 요청 ID, BOOTTIME 기한을 적용하며
보존을 삭제하지 않고 진행 중 집행을 폐기합니다. 독립 수신자·적대적 응답을 포함한
생성 mTLS fixture 검사가 통과했지만 실제 배포 호패 소유자가 아닙니다. 네이티브
권한·permit 소비자, 쌍 ledger 보존, 최종 출력은 아직 전환하지 않았습니다.
소비자 적용은 인증된 digest-only 요청·동적으로 검증한 신원·프로세스 도메인
부트스트랩도 해결해야 하며 요청마다 채널을 만들거나 들어오는 원천 pin을 신뢰하면
안 됩니다.
초안 릴리즈와 교차 호스트
Kubernetes gate도 계속 열려 있습니다.
