# ADR 0020: 통합 제로트러스트 콘솔 재설계

[English](../adr/0020-unified-console-redesign.md)

상태: **제안(Proposed)**. [CONSOLE.md](CONSOLE.md)의 구성요소별 메뉴 배치와
[2026-10-15 관리자 UI 검토](2026-10-15-admin-ui-review.md)의 메뉴 결정을 대체하되,
그 신뢰·broker·고정(pinning)·수명주기·감사 불변식은 유지합니다. 판정 데이터는
[ADR 0019](0019-decision-events-exporter.md)에 의존합니다.

## 배경과 품질 기준

목표는 Cloudflare Zero Trust, Okta, Teleport, Tailscale 관리 콘솔에 견줄 **상용 수준
관리 제품**입니다. 이 ADR은 최소 콘솔이 아니라 제품 요구사항을 정합니다. 각 화면은 아래
수용 기준을 EN·KO, 라이트·다크, 데스크톱·390 px에서 모두 통과해야 완료입니다.

검토 결과 현재 콘솔은 이 기준에 미달합니다.

- 메뉴가 운영자 작업이 아닌 구성요소(호패, 수문장, 품계)별로 나뉘어, 거부된 요청 하나를
  조사하려면 메뉴 세 곳을 오가야 합니다.
- 플러그인마다 HTML/JS를 직접 작성합니다. 수문장은 렌더링 뒤 `MutationObserver` 사전으로
  영어를 한국어로 바꾸므로 사전에 없는 문구가 새어 나오고, 호스트도 영어 문장을 번역 키로
  씁니다.
- 원본 JSON `<pre>` 출력, JSON textarea 편집, snake_case 필드명이 주 UI이며 검색·필터·
  정렬·페이지네이션·상세 화면이 없습니다.
- 게시에 구조화된 diff, 영향 미리보기, 확인, 사유가 없습니다. 감사가 흩어져 있고 호스트
  journal(`GET /v1/plugins/audit`)에는 UI가 없습니다.
- subject가 호패 신원으로 해석되지 않은 불투명 해시(`s_…`, `human1:…`)로 보이고
  사용자 → 권한 → 판정 → 네트워크 간 상호 링크가 없습니다.
- 무엇보다 모든 비교 제품에 있는 구성요소 간 판정 로그와 what-if 정책 시뮬레이터가
  없습니다.

| 기능 | 비교 제품 | 이곳의 요구 |
| --- | --- | --- |
| 단계별 사유가 있는 접근/판정 로그 | Cloudflare Access 로그, Okta System Log, Teleport 감사 | 판정 로그 + 요청 타임라인(P0) |
| 게시 전 정책 시뮬레이션·테스트 | Okta Access Testing Tool, Tailscale ACL 테스트/미리보기 | what-if 패널, 영향, 사유가 있는 CAS 게시(P1) |
| ID가 아닌 사람 표시와 엔티티 화면 | 네 제품 모두 | 엔티티 경로 + subject 해석(P0) |
| 전후가 있는 통합 관리 감사 | Okta, Teleport, Cloudflare 감사 로그 | 통합 감사(P0) |
| 일관된 디자인 시스템과 현지화 | 네 제품 모두 | 호스트 UI 키트 + 키 기반 i18n(P0) |

## 결정

콘솔을 **운영자 작업** 중심의 **8개 섹션**, 공유 **엔티티 경로**, 호스트 제공 **UI 키트**,
**키 기반 i18n**, 그리고 도메인 패키지가 독립 화면을 소유하지 않고 공통 섹션에 데이터
제공자와 뷰를 기여하는 **플러그인 계약 v2**로 재구성합니다. 소유권은 바뀌지 않습니다.
콘솔은 권한 주체에 대한 인터페이스이며 두 번째 작성자가 아닙니다(ARCHITECTURE.md).

영역은 제로트러스트입니다.

### 공유 엔티티 경로

| 경로 | 엔티티 | 주 소유자 |
| --- | --- | --- |
| `/identities/users/:id` | 호패 사용자(안정적인 불투명 ID) | 호패 |
| `/identities/sessions/:id` | 호패 세션 | 호패 |
| `/policies/services/:id` | 자원/역할을 포함한 품계 서비스 | 품계 |
| `/policies/roles/:service/:role` | 권한/등급/AAL을 갖는 역할 | 품계 |
| `/network/ip/:ip`, `/network/asn/:asn` | 주소 / ASN | 수문장 |
| `/access/requests/:request_id` | 요청 판정 타임라인 | exporter |
| `/audit/events/:id` | 관리 감사 기록 | 원천 권한 주체 |
| `/system/components/:id` | 구성요소 인스턴스 | 호스트 |

어디서 표시되든 모든 참조는 키트의 **엔티티 링크**를 씁니다. 사람이 읽는 이름이 먼저,
불투명 ID는 보조(고정폭, 복사 버튼)이며 소유자·상태·신선도를 보여주는 hover 카드가
있습니다. 링크는 직접 접근 가능하고 새로고침·뒤로/앞으로를 유지하며 목적지가 다시
인가합니다. **subject 해석**: 호스트가 화면별 미해석 subject 참조를 모아 호패 신규
`subjects/resolve` 작업(≤100 ID, 읽기 전용, 읽기로 감사)에 보내 표시 이름, 주체 종류,
상태, 프로바이더를 받습니다. 해석할 수 없으면 빈칸이 아니라 *알 수 없는 subject*와 ID를
표시합니다. ADR 0019 가명 참조는 `reveal` 또는 정방향 조회로만 해석됩니다.

## 화면 명세와 수용 기준

공통 화면 골격: breadcrumb, 제목, 소유자/설명, 주요 작업, **권한 주체 띠**(소유자,
리비전, 신선도, 읽기 전용/불가 상태), 필터, 본문. 없음·0건·오래됨·비활성·읽기 전용·
불가는 시각적·문구로 구분합니다. 모든 목록은 서버측 검색·필터·정렬·cursor 페이지네이션을
갖고 URL에 필터 상태를 담습니다. 빈 상태는 이유와 할 일을 설명하고, 오류는 소유자와
재시도를 보여줍니다. 보존 이벤트 1,000만 건 로컬 저장소에서 첫 행 표시 p95 ≤1초,
상호작용 지연 ≤100 ms.

### 1. 개요

구성: 권한 주체 상태 카드(한강, 호패, 수문장, 품계, exporter: 상태, 리비전, 마지막 게시,
신선도); 1시간/24시간/7일 판정 KPI(지표 기준 평가 요청, 거부율, 추가인증, 불가), 상위
거부 사유, 상위 거부 라우트, 상위 출발 ASN; 열린 위협 대기열·ASN 제안 수; 최근 관리
변경; exporter 유실/지연.

수용 기준: 모든 타일이 그 값을 만든 사전 필터 목록으로 연결됨; 숫자는 원천과 기간을
밝히고 샘플 추정치를 표시; 실패한 원천은 0이 아니라 소유자와 함께 *불가*로 표시; 원본
JSON 없음; 갱신은 최대 30초마다, 화면이 숨겨지면 중단.

### 2. 접근

**판정 로그**(`/access/decisions`). 필터: 기간(프리셋 + 절대), 결과, 결정 단계, 사유,
라우트/서비스/자원, 사용자(엔티티 선택기), IP 또는 프리픽스, ASN, 국가, 주체 종류,
정보등급, 리비전. 열: 시각, 결과 배지, 사용자, 라우트/서비스, 결정 단계, 사유(현지화
문장), 출발지(ASN/국가), 리비전. 콘솔 계정별 저장된 보기; 실시간 tail(≤5초 폴링,
제한); CSV 내보내기(≤1만 행, 공개하지 않으면 가명, 감사).

수용 기준: 필터가 결합되고 URL에 반영됨; 전역 검색에 `request_id`를 붙여넣으면 요청이
열림; 거부 행은 현지화된 한 문장으로 사유를 설명; suppressed 요약은 건수를 표시; 비활성
프로필은 시스템으로 가는 링크와 함께 *판정 이벤트 비활성*을 표시; strict 프로필은 가명을
보이고 사용자 상세에서 정방향 조회를 제공.

**요청 상세**(`/access/requests/:id`). 머리: 결과, 시각, 요청 참조번호, 라우트,
서비스/자원/행위. 단계 타임라인(네트워크 → 신원 → 인가 → 집행)에 단계별 판정, 사유,
엔티티 링크로 된 일치 규칙/역할, 리비전, 지연을 표시하고 결정 단계를 강조해 *이유*를
설명합니다. 현재 리비전이 다르면 리비전 벡터에 *이후 변경됨*을 표시합니다. 작업:
*시뮬레이터에서 재실행*(미리 채움), *사용자 열기*, *IP 열기*, *출발지 차단*(확인이 있는
네트워크 작업으로 이동).

수용 기준: 모든 품계 `Decision` 변형과 수문장/호패 판정에 전용 현지화 설명과 해결
안내가 있음; 도달하지 않은 단계는 이유와 함께 *평가 안 됨*으로 표시; 시뮬레이션
이벤트는 눈에 띄게 구분.

**시뮬레이터**(`/access/simulate`). 입력: 사용자(또는 익명), 주체 종류, 대상(호스트 +
메서드 + 경로 또는 서비스/자원/행위), 출발 IP, 선택적 가정 AAL/인증요소, 정책 원천(게시
또는 초안). 출력: 요청 상세와 같은 단계 타임라인, 평가 리비전과 함께 *시뮬레이션* 표시.

수용 기준: 같은 스냅샷에서 집행과 결과 일치(변형별 계약 테스트); 세션·permit·변경을
만들지 않음; 모든 실행 감사.

### 3. 신원

**사용자** 목록: 이름/이메일/ID/프로바이더 서버측 검색, 상태·프로바이더·주체 종류·마지막
로그인 필터, 확인이 있는 일괄 비활성화. **사용자 상세**(`/identities/users/:id`) 탭:
프로필(상태, 프로바이더, 생성, 마지막 로그인, AAL 가능 수준), 세션(AAL·인증요소·ASN·
경과 시간이 있는 활성 세션, 개별/전체 종료), 접근(서비스별 품계 할당과 역할·등급·실효
권한, *접근 확인*으로 시뮬레이터 열기), 최근 판정(ADR 0019, 사용자로 필터), 인증
이벤트(호패), 감사(이 사용자에 영향을 준 변경). **세션**, **프로바이더**, **인증 프로필**
(폼 편집기 + diff + 게시), **자격증명 투영**(ADR 0014, 같은 편집기)이 섹션을 구성합니다.

수용 기준: 어떤 판정·감사 기록·권한에서도 한 번의 클릭으로 사용자에 도달; 비활성화·종료는
사용자 이름과 사유를 요구하는 확인 후 결과 상태를 표시; 호패 native와 한강 위임 권한
모드가 보임; 콘솔 계정은 여기 표시하지 않음(시스템 참고).

### 4. 정책

**서비스·자원** 카탈로그, **역할·할당**(누가 어느 서비스에서 어떤 역할을 갖는지, 편집
가능한 할당 표), **정보등급**, **게시 이력**(행위자·사유·diff가 있는 리비전 이력, 롤백은
새 게시로). 모든 편집기는 **공통 정책 편집기**를 씁니다. 구조화된 폼(기본적으로 JSON
textarea 없음) → 소유자 검증 → 엔티티별로 묶은 **구조화된 diff** → **what-if**(시뮬레이터
케이스 + 선택 기간에 대한 ADR 0019 영향) → 기준 리비전과 필수 사유가 있는 **CAS 게시**
→ 새 리비전 결과.

수용 기준: 오래된 기준 리비전은 초안을 보존하고 새 변경을 보여주는 충돌 화면이 됨; 검증
통과 전 게시 불가; 영향이 결과 1건 이상을 바꾸거나 `restricted`에 닿으면 서비스 이름
입력 확인 필요; 초안은 이동·언어 전환·새로고침에도 유지(ADM-01).

### 5. 네트워크

**위협 대기열**(증거가 있는 수문장 후보, 승인/기각, 일괄), **차단·허용 목록**(검색, 만료,
사유, 소유자, 제거 확인), **규칙**(observe/enforce 모드·적중 수가 있는 순서 규칙 표,
CodeMirror 편집기의 Lua 본문, 저장 전 검증, ADM-02 CAS 리비전), **ASN 제안**(트래픽 증거와
영향이 있는 ASN 허용/거부 제안), **IP 상세**(`/network/ip/:ip`: GeoIP/ASN, 일치 규칙, 차단,
위협 후보, 그 주소의 최근 판정, 작업).

수용 기준: observe 모드 규칙은 enforce 규칙과 시각적으로 구분; 어느 화면에서든 차단은
확인 전에 대상·범위·만료를 표시; 전체 정책 교체는 항상 기준 리비전을 포함.

### 6. 단말·워크로드

워크로드 주체와 Kubernetes 서비스 계정 연결(ADR 0015), mTLS 신원과 투영, 최근 워크로드
판정. 단말 상태는 열린 설계(ADR 0005)이므로 *구성되지 않음*을 표시하며 정상으로
표시하지 않습니다.

수용 기준: 워크로드 subject도 사용자처럼 해석; 알 수 없는 단말 증거를 신뢰로 표시하지
않음.

### 7. 감사

호스트가 다음을 연합한 단일 타임라인: 콘솔 계정 감사(한강), 플러그인 작업 journal
(`/v1/plugins/audit`), 품계 게시(`/v1/audit`), 호패 관리 이벤트, 수문장 정책 변경(신규
읽기 작업). 열: 시각, 행위자(콘솔 계정과 발급자), 작업, 대상 엔티티 링크, 결과
(`committed`, `refused`, `uncertain`), 사유, 전후 해시, 작업 ID. 원천이 보존하면 상세에서
구조화된 diff를 보입니다.

수용 기준: 원천별 부분 실패를 활동 없음이 아니라 명시적으로 표시; 행위자·대상·작업·
원천·결과 필터; `uncertain` 결과는 안내와 함께 강조; 비밀·원본 본문 없음; 내보내기 감사.

### 8. 시스템

구성요소·버전, 서명된 업데이트 상태/확인, GeoIP DB, 원천 신선도·진단, 설치 패키지와
manifest 고정값, 콘솔 계정·역할, exporter와 개인정보 프로필 상태. **원본 JSON은 여기서만**
읽기 전용으로, 진단용 *원본 보기* 펼침 뒤에 제공합니다.

수용 기준: 버전 불일치와 오래된 원천 표시; 업데이트 작업은 버전과 사유 확인 필요.

## 와이어프레임

와이어프레임은 영문 원문과 같습니다(화면 문구는 메시지 키로 현지화). 개요, 판정 로그
목록, 요청 상세 타임라인, 사용자 상세, 정책 게시 diff의 다섯 화면은
[영문 ADR의 와이어프레임 절](../adr/0020-unified-console-redesign.md#wireframes)을
참고합니다. 아래는 요청 상세의 한국어 표시 예입니다.

```
+--------------------------------------------------------------------------+
| 접근 ▸ 요청 ▸ hg-7f3a9c2e41d08b65                   [시뮬레이터 재실행]  |
| 거부 403 · 2026-10-16 09:12:44 · GET app.example.test /api/reports/{id}  |
| 서비스 reports · 자원 report · 행위 read                                 |
+--------------------------------------------------------------------------+
| ● 네트워크  허용(enforce)  규칙 asn-allow-corp  rev 418          41 µs   |
| ● 신원      인증됨         Kim Analyst(사람) · oidc-corp · AAL1  183 µs  |
| ✖ 인가      등급 거부      역할 analyst에 restricted 등급 없음    22 µs   |
|   해결: 등급 부여 또는 추가 인증 요구  [역할 열기] [변경 시뮬레이션]      |
| ○ 집행      거부           의무 없음 · fence 정상 · 한강 268             |
+--------------------------------------------------------------------------+
| 리비전: 한강 268 · 수문장 418 · 호패 5521 · 품계 77 (현재 78!)           |
+--------------------------------------------------------------------------+
```

## 디자인 원칙

1. **기본적으로 원본 JSON 없음.** 폼·표·구조화된 diff를 쓰고 JSON은 시스템 진단에서만.
   필드 레이블은 snake_case가 아니라 메시지 키에서 가져옵니다.
2. **파괴적이거나 보안을 낮추는 작업**(비활성화, 종료, 차단, 삭제, 게시, enforce→observe
   전환)은 대상 이름, 효과, 감사에 기록되는 필수 사유로 확인합니다.
3. **상태에 맞는 작업만.** 비활성 사용자에는 *비활성화*가 아닌 *활성화*를 보이고, 읽기
   전용 원천은 비활성 버튼 대신 읽기 전용인 이유를 보입니다.
4. **거부를 설명.** 모든 거부는 어느 권한 주체가 왜 결정했는지와 해결책을 보입니다.
5. **사실대로의 상태.** 신선도·리비전·불확실성은 항상 보이며 알 수 없음을 정상·0·허용으로
   표시하지 않습니다.
6. **ID보다 사람.** 해석된 이름이 먼저, ID는 보조이며 복사 가능.
7. **모든 것이 연결.** 모든 엔티티 참조는 엔티티 링크입니다.
8. **반응형·접근성.** 390 px에서 표는 카드 목록, 필터는 시트, 타임라인은 세로로 쌓이며
   코드 편집기와 diff만 가로 스크롤합니다. WCAG 2.2 AA: 키보드 도달, 보이는 포커스,
   레이블 있는 컨트롤, 비동기 결과의 `aria-live`, 색만으로 신호하지 않음, 동작 줄이기 지원.

## 공유 UI 키트

호스트는 버전 있는 vanilla ES 모듈 묶음 `@hangang/console-ui`(`/ui/kit/1/`에서 제공,
호스트 빌드와 고정 자산의 일부)를 배포하고 마운트에 `context.ui`로 전달합니다. 패키지는
키트 URL을 직접 import하지 않으므로 키트와 호스트 버전이 어긋나지 않습니다. 구성요소:

- 서버측 검색/필터/정렬/cursor 페이지네이션, 열 선택, 행 선택, 일괄 작업, 390 px 카드
  배치, URL 상태 동기화를 갖는 **DataTable**.
- **FilterBar**, 기간 선택기, 저장된 보기.
- **EntityLink**와 hover 카드, **SubjectResolver** 일괄 해석.
- **StatusBadge**, **FreshnessBadge**, **AuthorityStrip**.
- 필드 스키마에서 생성되고 메시지 키의 레이블/도움말, 소유자 검증 메시지, 초안 보존
  (ADM-01)을 갖는 **폼 컨트롤**.
- 기존 CodeMirror 빌드(`web/lua-editor.js`)를 감싼 **CodeEditor**.
- **StructuredDiff**(엔티티별 추가/삭제/변경)와 텍스트 diff.
- **WhatIfPanel**과 **StageTimeline**(요청 상세와 시뮬레이터 공용).
- 호스트 토큰 팔레트를 따르는 **차트**(sparkline, 시계열, 막대).
- 대상 이름 재확인, 효과 요약, 필수 사유가 있는 **ConfirmDialog**.
- **EmptyState**, **ErrorState**(소유자 + 재시도), **UncertainOutcome** 배너.

모든 구성요소는 신뢰할 수 없는 문자열을 텍스트 노드로 렌더링하고 호스트 CSP(`unsafe-eval`
없음, inline script 없음)를 지키며 River 테마 토큰을 씁니다.

## 국제화

- 패키지는 키(`guard.rules.mode.observe`) 기반 메시지 카탈로그 `messages/en.json`,
  `messages/ko.json`을 ICU 형식 복수/선택 파라미터와 함께 제공합니다. 호스트는
  `context.t(key, params)`를 제공하고 기존 `onLocaleChange` 계약으로 초안 손실 없이 다시
  렌더링합니다.
- **사후 DOM 번역 금지**: `MutationObserver`나 문구 대조 사전을 쓰지 않습니다. 호스트도
  영어 문장 키 사전(`web/locales/ko-*.js`)을 키 기반으로 이전합니다.
- 없는 키는 영어로 대체하되 집계하고 CI를 실패시킵니다. lint 규칙은 `textContent`,
  `innerHTML`, `title`, `placeholder`, `aria-*`에 전달되는 문자열 리터럴을 거부하고 EN·KO
  카탈로그의 키 집합이 같은지 검사합니다.
- 사유 코드(ADR 0019)와 필드명은 두 언어 모두 등록된 키를 갖습니다.

## 플러그인 계약 v2

플러그인은 **도메인 데이터 제공자 + 공통 섹션에 마운트되는 뷰**가 됩니다. 신뢰 모델은
그대로입니다. 운영자가 검토한 패키지, manifest SHA-256 고정, 해시·크기 제한 자산, 신뢰
코드의 같은 출처 `import()`(sandbox 아님), 명시적 작업 허용 목록을 가진 호스트 API broker,
행위자 재검증, 서버측에만 있는 서비스 자격증명, 비공개 변경 감사, 세션 세대 fence입니다.

manifest 추가 항목(`api_version: 2`)은 영문 원문의 JSON 예시와 같습니다:
`kit`, `messages`, `contributes.pages`(섹션·경로·제목 키·모듈·작업·권한),
`contributes.entities`, `overview_cards`, `decision_stage`, `audit_source`, `search`.

- 호스트가 섹션, 경로, breadcrumb, 제목, 권한 주체 띠, 권한 검사를 소유합니다. 화면
  모듈은 지금처럼 `mount(context)`를 export하며 `root`, `signal`, `api`, `locale`,
  `onLocaleChange`에 더해 `ui`, `t`, `navigate`, `link(entity)`, `params`를 받습니다.
- 콘솔 권한은 범위형(`decisions:read`, `decisions:reveal`, `decisions:trace`,
  `policy:write`, `network:write`, `identity:write`, `audit:read`, `system:admin`)이 되고
  작업마다 서버측에서 강제됩니다. viewer 접근은 CONSOLE.md가 이미 요구하듯 작업별 명시
  정책이 필요합니다.
- **이전.** 호스트는 v1과 v2 패키지를 함께 로드합니다. v1 패키지는 *레거시* 묶음 아래
  현재의 단일 메뉴 마운트와 지원 중단 안내를 유지합니다. Guard와 호패는 섹션 화면으로
  나눈 v2 패키지를 배포하며, 두 v2 패키지가 검증된 뒤 다음 minor 릴리즈에서 v1 지원을
  제거합니다.
- **품계**는 호스트 내장 코드(`web/pumgye.js`)에서 같은 broker·서명·고정을 쓰고 자체
  백엔드 바인딩을 갖는 `pumgye` v2 패키지로 이동합니다.

## 검토한 대안

- **각 플러그인을 그대로 다듬기.** 기각: 구성요소 형태의 메뉴와 구성요소 간 데이터 부재가
  남아 비교 작업을 수행할 수 없습니다.
- **번들러와 SPA 프레임워크(React/Vue) 도입.** 현재는 기각: 신뢰 로더·CSP·고정 모델과
  기존 vanilla 호스트에는 vanilla ES 키트가 맞습니다. 키트가 부족하면 재검토합니다.
- **iframe 격리 플러그인.** 기각: 메뉴·엔티티 링크·키트를 공유할 수 없고 같은 출처 신뢰
  코드에 대한 보안 경계도 아닙니다.
- **콘솔에서 통합 허용 계산.** 기각: 판정은 권한 주체 explain API에서만 옵니다.

## 결과

- 운영자는 작업 단위로 일하며 연결된 엔티티, 설명된 거부, 게시 전 시뮬레이션, 하나의
  감사 흐름을 얻습니다.
- 세 패키지와 호스트를 키트와 v2 계약으로 다시 작성해야 하며, UI 검증 관문이 있는 여러
  릴리즈 규모의 작업입니다.
- 새 소유자 API가 필요합니다: 호패 `subjects/resolve`와 인증 explain, 품계 `/v1/explain`과
  배치 explain, 수문장 후보 lookup과 감사 조회.
