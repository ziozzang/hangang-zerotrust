# 통합 관리자 콘솔 검토

[영문 원문](../reviews/2026-10-15-admin-ui.md)

상태: Astra 세 검토자가 소스와 구현 수용 기준을 검토했다. 현재 브라우저·배포
검증을 수행한 것은 아니다. 이전 화면 자료는 외관 참고이며 현재 동작의 증거가 아니다.

## 메뉴 설계

한강을 콘솔 shell과 게이트웨이·라우팅 소유자로 유지한다. 현재 소스도 세 권한
모듈을 Zero Trust에 모으므로 호스트가 순서를 명시적으로 관리한다.
**신원 · 호패 → 네트워크 신뢰 · 수문장 → 접근 권한 · 품계**를 권장한다.
`guard` 등 기존 ID·hash 주소는 호환 별칭으로 유지한다. 콘솔 계정, 호패 신원,
품계 서비스 권한을 구분하고 기존 River 테마·토큰을 재사용한다.

공통 화면은 경로, 기능 제목·소유자 설명, 작업, 권한 원천·소스·신선도·리비전,
하위 메뉴와 실제 작업 영역으로 구성한다. 전역 한강 연결·리비전은 모든 원천의
정상이나 접근 허용을 뜻하지 않는다. 미확인·0건·오래됨·비활성·읽기 전용·장애를
구분한다. 장부·사초 관측과 사헌·실록 증거 영역은 실제 설치·인가된 기능이 생길
때까지 설계 슬롯으로만 둔다.

## 소스로 확인된 문제와 한계

한강은 품계 메뉴로 돌아올 때 다시 읽어 dirty draft를 초기화한다. 호패도 resume·탭
읽기가 추적하지 않는 편집기를 교체한다. 저장 대기 중 만든 새 편집이 이전 저장
응답에 덮일 수도 있다. 플러그인 화면은 footer 뒤에 붙는다. 품계는 작은 모니터링
표 스타일을 빌리고 플러그인 언어·탭 의미도 일관되지 않다. 수정 완료를 주장하려면
실행 가능한 fixture 회귀 검사가 필요하다.

수문장은 호출자의 리비전 없이 전체 정책을 교체하므로 엔진 쓰기를 직렬화해도
오래된 draft를 발견하지 못한다. allowlist의 GET→PUT도 경합한다. 이는 인가된
변경의 유실이며 인증 우회가 확인된 것은 아니다. 호스트의 전송 후 권한 회수는 이미
완료된 작업의 응답과 추적 번호를 숨길 수 있다. 최종 권한 fence는 유지하면서
회수된 본문 노출 없이 결과 표현을 고쳐야 한다. 원천 권한 거부와 인프라 장애도
안전하게 구분해야 한다.

현재 호스트 플러그인 발견·API는 관리자 전용이다. 메뉴·버튼 표시만 바꿔 viewer
권한을 늘려서는 안 된다. 호패 native 권한과 명시적 한강 위임은 서로 다른 모드이며
실패 시 우회 수단이 아니다. 품계 백엔드 감사의 peer만으로 브라우저 사람을 증명하지
못한다. UI 개선 중에도 이 경계와 추적 관계를 유지한다.

## 구현 소유권과 검증

주요 파일은 한강 `web/app.js`, `plugins.js`, `pumgye.js`, `index.html`, `style.css`,
호패 `plugins/hopae/index.js`, 수문장 dashboard 원본과
`tools/build_console_plugin.py`이다. Guard 패키지는 생성물이다. 출력만 고치면
덮이므로 lifecycle·배치를 바꿀 때 생성과 검토한 manifest hash 고정을 함께 수행한다.

기존 console·품계·플러그인 lifecycle·다국어 fixture를 확장한다. 화면 캡처는 예약된
예제 데이터와 정확한 소스·빌드를 기록한다. 밝음·어두움, EN·KO, 대표 데스크톱·모바일,
키보드, 오래됨·빈 상태·충돌·권한 상실을 검증한다. 실제 소유자 API 동시성·전송 후
변경 검사가 시각 검사를 보완한다. 전체 검토와 후속 구현 계획은 비공개 검토 보관소에
보존하고 [작업 큐](ASTRA_REVIEW_QUEUE.md)로 적용을 추적한다.
