# 네이티브 관측 소비자 적용

상태: Sol 6.1 소스 검토·구현 인계이며 소비자 구현 완료가 아니다. 기준 소스는
호패 `2a96303`, 품계 `34d74b6`, 한강 `b41b492`다.
[English](../reviews/2026-10-15-native-observed-adoption.md)

## 구현 갱신

안정 정책·digest SDK는 호패 `c7ddcf2`, 별도 품계 관측 인증 어댑터는 `97bf852`에
구현했다. 어댑터는 빌린 ArcSwap 세대 검사·게시 전 폐기를 사용하며 외부 콜백은
네이티브 guard 밖에서 실행하고 콜백 뒤 BOOTTIME을 확인한다. 기능 workspace 78개·
엄격한 Clippy·기본 locked 검사가 통과했다. 근거 라이브러리 연결이며 관측 권한
endpoint·permit 발급은 활성화하지 않았다. 아래 기존 분석은 해당 인터페이스가
필요한 이유를 기록한다. 별도 품계 선행 조건/permit 시계·쌍 replay·출력에 이어
실제 최종 집행 검증 순서로 진행한다.

## 기존 다음 코드 경계

정확한 pin SDK는 검증한 기반이지만 운영 소비자가 그대로 사용할 수는 없다.
품계는 인증된 최종 요청 digest를 받으며 HTTP 메서드·경로·본문을 소유하지 않는다.
한강은 최종 엔티티를 이미 한 번 해싱한다. 둘 다 동적으로 검증한 서비스 신원을
다루지만 현재 클라이언트는 주체·프로필/앱 세대·임의 원천 프로세스 도메인을 고정한다.
들어오는 문맥으로 요청마다 클라이언트를 만들면 입력을 신뢰로 승격하고 연결 재사용·
수명주기 소유권을 잃는다.

기존 정확 모드를 유지하며 서버가 컴파일한 안정적 서비스 신뢰 정책·digest 준비
API를 별도로 추가한다. 지속 네이티브 클라이언트가 발급자·키·기본 신원·서비스/대상
범위·리비전 하한·TLS 주소·시계 모델·비공개 수명주기 seal을 소유한다. 발급 의도는
네이티브 최종 digest·헤더에 결합한다. 관측 질의는 문맥의 구조·정책 검사와 인증된
집행 호출자의 기대 digest 일치를 확인한 뒤 불변으로 보관한다. 준비는 권한이 아니다.
서명 검증과 고정된 현재 소유자 RPC가 모두 성공해야 비공개 시간 근거를 만들며,
품계가 같은 서명을 다시 검사하지 않고 검증된 불변 근거를 재사용한다.

## 프로세스 도메인과 로컬 소유권

운영자는 임의 프로세스 도메인 대신 안정적인 신뢰를 설정한다. 새 작업에서 서명된
문맥의 도메인을 읽고 인증된 현재 소유자 보고와 정확히 일치시킨다. 그러면 새 프로세스
증명은 설정 수정 없이 동작하고 원천이 이전 프로세스 증명을 거부한다. 갱신은 증명의
도메인을 바꾸지 않는다. 이는 주소 발견·임의 replica 분산 해결이 아니다. 새 도메인·
거부 응답만으로 replay 레코드를 삭제해서는 안 된다.

registry 하한은 네이티브 소유자·설정 범위에 둔다. 하나의 프로필 카운터로 서로 다른
서비스 신원을 합치지 않는다. await 전체에서 불변 신뢰/클라이언트 세대를 캡처하고,
교체 전에 폐기하며 권한·서명·출력 직전 활성 Arc 동일성을 재검사한다. 시점 관측은
회수 lease가 아니다.

## 구현 순서와 수용 기준

1. 안정 정책·digest SDK를 추가한다. 지속 클라이언트 하나에서 여러 서명 주체·도메인,
   고정 신뢰/범위/하한 거부, 설정 수정 없는 재시작, 도메인 불변 갱신, 새 요청 ID,
   폐기·취소를 검사한다.
2. 별도 품계 관측 인증 래퍼를 추가한다. 가짜 UTC나 기존 엄격 checked 타입으로의
   변환 없이 검증 신원·로컬 시간 근거를 소비한다. 이 분기의 permit 발급은 아직 끈다.
3. 선행 조건을 품계 로컬 수신자 도메인으로 옮기고 잔여 예산을 교차한 뒤 품계의
   별도 진행 원천 도메인으로 permit을 서명한다. 인증 계보는 permit 시계가 아니다.
   관측 permit envelope를 추가한다.
4. 호패 영속 쌍 replay·최종 출력을 함께 바꾼다. 원자적 nonce 예약·registry 검사·
   비밀 조회·최종 fence·commit을 유지한다. 엄격/관측 행을 버전으로 구분하고 원천
   만료·수신자 벽시계 대신 수신자 보존 기한으로 정리한다. 수신자 재시작을 정의한다.
5. 관측 출력 envelope·한강 변환·최종 전달 fence를 추가한다. 인증·permit·출력·수신자
   시계를 분리하고 독립 offset·비대칭 지연·절전·경합·취소·응답 유실·재시작/복구·
   실제 최종 백엔드 효과를 검증한다.

이 단계 뒤에 서명 재빌드·실제 네 Pod K8s/브라우저·운영 적용을 수행한다.
기존 엄격 경로는 전환 과정에서도 별도로 유지한다.

## 출력 유효 시간 SDK와 진행 중인 네이티브 통합

호패 SDK `e01c67e`에 `ClockRates::remaining_admission_until`과 읽기 전용
레지스트리 세대 조회가 추가되었다. 요청 전 수신자 시각에 전체 RPC 시간을
청구하고, 독립 시계의 양자화와 명시적인 속도 오차를 고려하며 불연속·범위
초과를 거부한다. 반환값은 숫자형 만료 하한일 뿐 인증 증거나 재사용 방지
보존 기간이 아니다. 네이티브·기본 SDK 테스트 및 전체 대상·기능 Clippy가
통과했다. 런타임 `bf3ba2c`의 단일 BOOTTIME 읽기는 은퇴 상태를 검사하며,
35개 테스트·엄격 Clippy·musl 라이브러리 검사를 통과했다.

품계 `6b2b781`과 호패 `4ffd3c5`는 각각 관측 permit·출력 응답 프로토콜을
추가했다. 실제 원천 소유자, 두 증명의 원자적 재사용 방지, 한강 최종 전달
통합은 구현·검증 중이다. 이 SDK·프로토콜 커밋만으로 전체 4개 프로세스,
독립 호스트, Kubernetes, 브라우저, 서명 릴리즈 또는 운영 배포 검증이
완료된 것은 아니다.
