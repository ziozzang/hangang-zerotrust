# 호패 공급자 완성 범위 근거

상태: Sol 6.1 읽기 전용 소스 감사이며 새 테스트 실행·운영 검증이 아니다.
기준 호패 소스는 `2a96303`이며 이후 시간 클라이언트 작업으로 아래 공급자 범위가
완료되지는 않는다.
[English](../reviews/2026-10-15-provider-completion.md)

## 재사용할 구현 경계

공급자 registry는 OIDC·LDAP를 실행한다. Google preset은 실제 구현이지만 강제
재인증 기능은 명시적으로 미지원이다. 소유한 OIDC 시나리오와 LDAP TLS/StartTLS
fixture가 프로토콜을 검사하며 enum만으로 로컬 비밀번호·이메일 링크·범용 OAuth2
공급자 구현을 주장할 수 없다. 네이티브 비밀번호 제출은 자체 비밀번호 DB가 아닌
LDAP를 인증한다(`src/provider/registry.rs`, `src/provider/ldap.rs`).

서비스 프로필은 자체 API 키·외부 API 검사·K8s TokenReview·네트워크 제약·명시적
접두부 라우팅을 구현한다. 자격 격리·만료/범위·네트워크·게시 경합·열린 서킷 유지
검사가 있다. `src/auth_gateway/mod.rs`의 제한된 Any/All helper는 운영 orchestration
호출자가 없다. 접두부 라우팅·네트워크 제약을 임의 공급자 조합 완료로 표현하지 않는다.

TOTP 등록/확인/제거·키 암호화, 소유자 결합 단일 사용 step-up, 외부 HTTPS MFA와
브라우저/네이티브 완료는 소스·소유 fixture 근거가 있다. Lua는 검증 신원에 대한
제한된 boolean 적격 검사이며 임의 커넥터 호출 조합·비밀 반출 기능이 아니다.
네이티브 전송·품계 서비스 권한 매핑·guest 거부는 기존 구현을 재사용한다.

## 남은 완성 작업

- 실제 혼합 공급자 조합·명시적 신원 관계를 연결하고 주체/서비스 분리·가장 짧은
  예산을 유지한다. 자체 사람 자격 공급자·수명주기 범위를 확립한다. 현재 LDAP
  로그인을 로컬 계정/비밀번호 지원 근거로 삼지 않는다.
- 서비스뿐 아니라 검증한 사람/워크로드 신원을 서명 권한·쌍 replay·서비스 자격
  변환·최종 전달에 연결한다. projection 라이브러리·서비스/AAL0 fixture만으로
  이 범위를 입증하지 않는다.
- 감사되는 요소/계정 교체·복구, 단일 사용 복구 인증 수준, 서비스별 등록/수용을
  완성한다. 기존 TOTP 성공은 요소 분실 복구 완료가 아니다.
- 승인된 확장 설계에서 필요한 제한된 커넥터 orchestration을 추가하되 신원·인증
  수준·세션·권한의 소유권은 네이티브에 둔다.
- 외부 디렉터리 변경에 따른 발급 세션 회수와 장기 스트림의 세대/공급자 회수를
  구현·검증한다. 기존 채널에서 프로필을 거부하는 검사와 구별한다.
- 실제 공급자/브라우저, 전체 체인 회수·거부 시 백엔드 미전달, 정확한 서명 자산,
  K8s·명시적으로 설정한 운영 경로를 검증한다. 실제 Google 사용자 상호작용과
  전체 체인 처리량은 소유 모의 공급자·컴포넌트 처리량 검사와 별도 조건이다.

이름만으로 무관한 SAML·중첩 그룹·introspection 범위를 추가하지 않는다. 원래의
전체 혼합 신원 범위를 유지하고 설계·소스 검사·릴리즈·활성 배포를 동일시하지 않는다.
