# 요청 바인딩 v2 순수 코덱

상태: 참조 규약과 합성 언어 간 벡터입니다. Human RPC·인증 증거·권한·라우트
활성화·전체 체인 검증이 아닙니다. [영문 규범](../reviews/2026-10-16-request-binding-v2.md).
ZT 기준0426f3b이며 기존v1 코드와 고정 벡터는 변경하지 않습니다.

이전 설계의 숫자까지 중첩 길이 프레이밍하는 설명 대신 다음만 사용합니다.
모든 정수는 부호 없는 빅엔디언, LP32는 u32길이와 원본 바이트입니다.
도메인v2+NUL → LP32 서비스/대상/라우트ID → u64라우트리비전 → 원시32목적지해시
→ LP32메서드/최종타깃 → u64실제본문길이/실제본문SHA256원시32
→ u64헤더정책리비전/u16슬롯수 → 이름정렬 슬롯 순서입니다.
각 슬롯은 LP32이름/존재u8이며 존재할 때만 LP32값을 추가합니다.
부재와 빈 값은 구별하며 누락·중복·미등록 슬롯은 거부합니다.
본문은 실제 완전한 바이트만 받으며 호출자 해시/길이 대체는 없습니다.

리비전은1..9007199254740991, 목적지32바이트는 영해시가 아니어야 합니다.
ID·메서드·타깃은 기존v1 검증을 따르고 정규화하지 않습니다.
본문<=16MiB, 헤더0..16개, 소문자RFC토큰이름<=128바이트,
값 각각<=1024/합계<=8192바이트입니다. TAB포함00..1f와7f를 거부하며
80..ff는 그대로 보존합니다. 빈 매니페스트도 양의 정책리비전이면 가능합니다.
정적 보안/프레이밍 헤더와 예약 접두사는 영문 목록대로 금지합니다.
실제 설정의 자격증명·호출자·신원 헤더도 최대64개 예약이름 입력으로 제외해야
합니다. 순수 코덱은 사용자 정의 자격증명 헤더를 알아낼 수 없습니다.

Python참조와JSON벡터는 전체 사전이미지16진수와 기대SHA를 제공합니다.
8개 테스트는 본문동일길이변조·소유필드변조·부재/빈값·순서·중복/누락·제어문자
·크기제한·v1고정SHA를 확인합니다. 다른 언어의 실제 통과를 아직 주장하지 않습니다.
네이티브 세션·동일 불변 요청·현재 소유자·원래 수명·최종 전송 검증은 후속 통합 책임입니다.
