# ADR 0008: 제한된 HOP1 검증과 콘솔 위임

[English](../adr/0008-hopae-native.md)

상태: Hangang/Hopae PR #1에서 수락·구현했습니다. 운영 적용과 플랫폼 검증은 별도 항목입니다.
16바이트 magic/u64 요청 ID/u32 payload 길이, ID 0 인증 핸드셰이크와 증가하는 양수 ID,
크기가 제한된 binary 헤더/본문을 사용합니다. 첫 버전은 message-type flag나 크기 협상을
대신해 고정된 한도를 사용합니다. Hopae는 기존 HTTP 검증 라우터를, Hangang은 동일한
신원·쿠키·terminal 결과 처리를 재사용합니다. 판단 캐시나 장애 후 HTTP 재시도는 없습니다.

정확한 byte order·한도·인증·수명주기는
[네이티브 계약](https://github.com/ziozzang/hopae/blob/main/docs/HANGANG_NATIVE.md)에 있습니다.
기존 HTTP 결과/헤더와 해당하는 만료 정보는 보존하지만 전체 통합 정책/세션 revision vector는 향후 과제입니다.

위임은 전용 issuer/backend 키·제한된 HMAC assertion·영속 nonce·경로/본문/handle/IP/UA 결합을
사용합니다. Hopae handle·grant·인증 강도·freshness·CSRF·트랜잭션 fence를 유지하고,
브라우저 방식은 Hangang 권한과 독립적인 Hopae 관리자 세션을 모두 요구합니다.
계정 자동 승격이나 DB 복제는 하지 않고 프로바이더 로그인/로그아웃은 Hopae에 유지합니다.

IP 프레임 재사용·프로바이더 중복·장애 후 HTTP replay·비서명 actor·모델 점수나 Hangang 역할을
Hopae grant로 취급하는 방식을 배제했습니다. 실제 세션 parity·엔트리·코덱·키/ID 거부·풀
취소/재연결/포화·프로바이더 기반 변경/회수·영속 nonce·감사·콘솔 수명주기를 검증했습니다.
이미 수락된 변경의 원자적 회수나 Guard 수치에 기반한 전체 identity 처리량을 주장하지 않습니다.

이후 명시적 통합 권한·SSO 모드는 [ADR 0009](ADR_0009.md)에 기록했습니다.
