# ADR 0009: 단일 콘솔 권한과 Hopae SSO

상태: 구현 완료, 배포 근거는 TODO에 기록합니다. [English](../adr/0009-console-authority-sso.md)

Hangang 아래의 Hopae 관리 화면은 Hangang 인증·역할을 따릅니다. Google/OIDC 및
사용자·세션 소유권은 Hopae에 유지합니다. SSO로 인증한 경우에도 콘솔 권한은
Hangang 계정의 역할을 적용합니다. 영어 문서에 전체 호출 다이어그램을 기록했습니다.

기본 native 모드는 기존 독립 Hopae grant/handle/freshness/AAL 정책을 유지합니다.
새 `hangang` 모드는 제한된 관리 API에 대한 Hangang 관리자 서명만 허용하며
네이티브 사용자를 위장하거나 Hopae grant를 만들지 않습니다. 권한 모드는 서명에
포함됩니다. 영속 일회성 nonce, 정확한 요청 바인딩, 5초 미만 proof를 요구하고
변경 트랜잭션에서 현재 키·만료·issuer 기반 actor/session 바인딩을 다시 검사합니다.
독립 Hopae 관리는 기존 정책을 적용합니다. 통합 모드의 인증 정책은 Hangang을 따르며
네이티브 로그인 시각/AAL을 임의로 만들지 않습니다. issuer·actor를 감사에 남깁니다.

SSO는 선택적인 네이티브 콘솔 broker 설정입니다. 불변 Hopae ID를 기존 활성 Hangang
계정에 명시적으로 연결합니다. 이메일/표시명으로 자동 연결하거나 provider claim으로
권한을 만들지 않습니다. 요청마다 Hopae 쿠키·원래 IP/UA를 확인하고 네이티브 검증을
수행합니다. 불투명 browser bearer는 parent API에서 직접 사용할 수 없습니다.
private Hangang lease는 5초, 재사용은 최대 1초입니다. 일반 계정이나 공개 어댑터로
system 전용 lease endpoint를 호출할 수 없습니다. 계정 활성 상태·역할을 다시 확인합니다.
비밀값·매핑은 private 설정에 보관하며 discovery는 provider명·고정 경로만 노출합니다.
같은 origin의 custom-header POST와 빈 JSON object로 교환하고 중복 헤더/쿠키를
거부합니다. 프로바이더 토큰은 Hopae에 유지합니다.

콘솔 로그아웃은 불투명 bearer와 현재 lease를 회수하며 다른 Hopae 앱을 전역
로그아웃하지 않습니다. 어댑터 재시작 후 SSO 교환은 기존 Hopae 로그인을 재사용할 수
있습니다. 다른 서비스가 이미 수락한 작업은 원자적으로 회수할 수 없습니다.

실제 Hangang 계정·SSO broker와 별도 HOP1 identity fixture로 매핑·다음 요청의 회수·
쿠키 바인딩·origin 거부·parent API 우회·로그아웃을 검증합니다. 브라우저 테스트는
버튼 위치·복귀·현재 역할·복구를, 실제 Hopae 시나리오는 native 회귀·통합 조회/변경·
모드 격리·만료·재전송·비서명 거부·감사를 검증합니다. 전체 처리량 검증은 별도 과제입니다.
