# 전체 구조와 소유권

[English](../ARCHITECTURE.md) · [목차](README.md)

Hangang은 라우트·리스너·백엔드·요청 집행을, Hopae는 프로바이더·사용자·세션·인증 강도를,
Guard는 IP/ASN/GeoIP·네트워크 위험을 소유합니다. 카탈로그는 리소스와 정보등급을,
정책 권한 주체는 접근 조건을 관리합니다. 같은 문서를 여러 서비스가 쓰는 구조로 만들지 않습니다.

제어 경로는 관리 콘솔 → 권한 주체 → 검증·컴파일 → 호환 번들 → CAS·원자적 게시 →
Hangang의 불변 스냅샷입니다. 카탈로그와 정책의 호환성을 함께 검증하며,
서로 다른 버전을 임의로 섞어 집행하지 않습니다.

요청 경로는 보호 네임스페이스와 리소스/작업을 먼저 확정하고 Hopae·Guard의 확인된 근거를
결합한 뒤 최종 정책을 집행합니다. 네트워크 허용은 사용자·리소스 권한을 대체하지 않습니다.
객체·테넌트·행 단위 접근은 애플리케이션의 실제 메타데이터와 연계합니다.

현재 컴포넌트의 일부 기능은 구현되어 있으나 전체 통합 엔진·카탈로그·exporter는 설계 단계입니다.
단말/워크로드 증거는 별도 검토가 필요합니다. 영어 문서의 도표와 현황 구분을 함께 참고하세요.

온톨로지는 Sillok, 자동·반자동 조율은 Jikji로 구성합니다. 펜테스트 근거를 바탕으로
Guard 정책과 Hangang 라우팅 패치를 연결하며 기존 도메인 소유권은 유지합니다.
[자동화 설계](AUTOMATION.md)에 적용 범위, 승인, 부분 실패 복구와 CAS 롤백을 정의합니다.

## Hearim 판단 백엔드

[Hearim(헤아림)](https://github.com/ziozzang/hearim)을 Jikji가 활용하는 지능·판단
백엔드 중 하나로 선정합니다. 문서화된 `POST /v1/systemone`의 Choice / Score / Noul과
logprob 기반 후보 분포를 판단 보조에 활용하며 다른 백엔드도 함께 사용할 수 있습니다.
실제 어댑터 통합은 구현 예정입니다. Sillok 온톨로지나 Jikji 실행 조율을 대체하지 않습니다.

모델·백엔드·판단 기준 리비전, 입력 근거 해시와 스코어링 진단을 보존하고 입력 최소화·
기한·동시성·테넌트 격리를 적용합니다. 후보 확률과 엔트로피 신뢰도는 보정된 공격 위험도나
정책 적용 권한이 아닙니다. 후보 누락/장애는 판단 불가 또는 검토 대상으로 처리하며
자동 허용으로 바꾸지 않습니다. 실제 변경의 권한·CAS·감사는 독립적으로 검증합니다.
일반 요청마다 추론 의존성을 추가하지 않으며, 재현 가능한 fixture·실패 응답·보정 근거·
개인정보 격리를 검증해야 합니다.

구현 갱신: Guard/Hopae 패키지·서명된 관리 위임·HOP1 검증·Hangang native 풀/진입 결과 처리를 머지했습니다.
[ADR 0008](ADR_0008.md)을 참고하세요. 온톨로지·분류·자동화 통합은 여전히 예정입니다.

운영 콘솔에서 두 메뉴와 네이티브 로그인/로그아웃 진입을 확인했고, 기존 Hopae 인증 라우트
10개에 HOP1 전송을 적용했습니다. Guard 서명 updater도 활성화했습니다. 전체 카탈로그·분류·
통합 리소스 정책·온톨로지/자동화 어댑터·exporter는 별도 구현 과제입니다.
