# Astra 검토·테스트 작업 큐

상태: 진행 중인 개발 큐이며 릴리즈 검증 완료를 의미하지 않는다.
[영문 원문](../ASTRA_REVIEW_QUEUE.md).

검토 수집 단계는 종료했다. 실행 중인 Astra 검토자는 없으며 아래 배정은 이전
배치의 기록이다. 구현은 보존된 발견 사항과 수용 기준을 꺼내 진행한다. 중단되어
저장하지 못한 후속 초안은 완료된 검토로 취급하지 않는다.

조정자는 범위를 정해 Astra에 검토를 맡기고, 반례와 테스트를 수집하고,
확인된 결함을 수정한 뒤 다음 작업을 배정한다. 검토는 실행 검증을 대체하지
않는다. 운영 코드 수정과 공용 Cargo 타깃 실행은 조정자가 관리한다.

## 진행 중

| ID | 작업 | 산출물 |
| --- | --- | --- |
| A1 | 권한 원천 시간 보안, 게시 경계, 시계 변경과 발급자 재시작 | 파일별 발견 사항, 반례, 결정적 회귀 테스트 설계 |
| A2 | 공개 SDK의 clock epoch 및 시간 구간 공격 테스트 | 독립 통합 테스트 파일; 조정자가 실행 |
| A3 | 모듈 간 시간 계약 전환과 영속 재사용 방지 안전성 | Hopae/Hangang/Pumgye 연결 지도, 실패 사례와 전환 조건 |

A1 초기 발견은 재현 대기 중이다. 외부 시계 호출 전에 읽은 프로파일을
교체 후 검사하면 이전 상태가 통과할 가능성이 있다. 게시 순서를 확인하고
결정적 회귀 테스트를 추가하기 전에는 수정 완료로 간주하지 않는다.

## 후속 작업

1. 최종 검증 중 게시 변경을 재현하고 애플리케이션, 키, 라우트, 네트워크,
   권한 스냅샷의 동일한 경계를 검토한다.
2. 발급자 재시작과 같은 키를 쓰는 다중 복제본의 clock domain 분리를
   검토한다. 서명자 신원과 실제 발급 프로세스 소유권은 구분한다.
3. 단축 관측, 갱신, 시계 전후 이동, 영속 재시작, 동시 소비에서 재사용
   방지 기록의 유지 시간을 검토한다.
4. 비대칭 지연, 밀리초 미만 경계, 필드 누락, 명시적 레거시 거부를 포함한
   독립 호스트 시간 관측 클라이언트 테스트를 설계한다.
5. 품계 permit 관측과 호패 projection 수신부 전환을 검토한다. 변환 전의
   만료 시각은 해당 소유자의 시간 도메인에만 속한다.
6. 새 RPC의 인증 연결 재사용, 취소, 동시 처리 상한과 입력 제한을
   검토한다. 분석 처리는 판정 경로 밖에 둔다.
7. 실제 네 서버의 K3s 기능 검증에 키 철회, 정책·프로파일 교체와 관리자
   브라우저 회귀 검사를 포함한다.

## 증거와 릴리즈 경계

기존 정적 네 서버 credential projection 검증은 통과했다. K3s 독립 호스트
receipt 클라이언트는 서명이 유효해도 엄격한 로컬 시각 검사에 실패했다.
시간 관측 원천 RPC와 clock domain 변경은 개발 중이며, 하위 모듈 적용과
전체 K3s 검증은 남아 있다. 수정된 산출물이 모든 기능 검증을 통과하기 전에는
초안 릴리즈를 공개하지 않는다. 검토만으로 성능을 주장하지 않는다.

초기 검토 산출물은 로컬에 두고, 저장소 문서에 반영하기 전에 민감한 정보가
없는지 확인한다.

## 첫 실행 결과

[검토 기록](2026-10-15-authority-time-review.md)에 확인된 증거, 한계와 통합
제안을 정리했다.

- A1은 소스 검토와 실제 프로파일 게시를 사용하는 결정적 회귀 패치를
  작성했다. 조정자가 최종 검사 순서의 잠정 수정을 적용했으며 회귀 실행과
  최종 재검증은 진행 중이다.
- A2가 작성한 공개 SDK 테스트 7개가 모두 통과했다. 물리적 시각 오프셋,
  밀리초 미만 위상, 비대칭 지연 조합 400개를 포함한다. 검증 범위는 수치 및
  암호학적 성질이며 인증 전송이나 재사용 방지 소비를 증명하지 않는다.
  A2는 시간 관측 RPC 장애 테스트 설계를 계속한다.
- A3은 전환의 필수 조건을 발견했다. 수신자 시계가 앞으로 이동해 nonce를
  정리해도 외부 원천의 증명은 살아 있을 수 있고, 새 상대 시간 관측으로
  다시 허용될 수 있다. 영속 단조 시간 소유권, 재시작과 발급 프로세스 고정을
  정의한 뒤에 재사용 방지 판정을 변경해야 한다.
- A1은 최종 출력의 취소·호출자·게시 경합을, A3은 발급자 고정형과 독립
  수신자형 설계를 후속 작업으로 진행한다.

## 후속 배치

- A1의 최종 출력 회귀 패치는 실제 호패 mTLS 검사에서 통과했다. 자원 검토는
  새 관측 요청 ID를 늦게 거부하는 문제를 찾았고 회귀 검사가 불필요한 인증
  실행을 재현했다. 관측 전용 조기 검사를 적용해 통과했다. 새 semaphore 누수,
  비밀 메타데이터 반사나 이전 규약 우회는 확인하지 않았다. 기존 protobuf
  디코딩 증폭은 별도 검토 항목이다.
- A2는 ID 조기 거부, 메타데이터, 처리 슬롯 하나에서 중첩 발급·재관측,
  취소 후 슬롯 복구의 네이티브 테스트 4개를 추가했다. 조기 검사 수정 후
  모두 통과했다. 다음 작업은 명시적 네이티브 호출자 역할 설계다.
- A3은 발급자 고정형 replay 설계를 작성했다. 같은 프로세스에서도 원천 가상
  시각과 수신자 단조 보존 시간은 분리해야 한다. 다음은 최소 공용 정적 타입과
  호환 전환 API 검토다.
- 추가 경계 테스트 4개 이전 소스 단계는 전체 968개 통과, 기존 제외 42개와
  엄격한 전체 대상 Clippy를 통과했다. 소스는 커밋했고 릴리즈 산출물과 기존
  운영 배포는 변경하지 않았다.

당시 후속 배정은 공용 gRPC 디코딩 자원 제한(A1), 네이티브 호출자 역할(A2),
공용 정적 관측 증거·ledger 인터페이스(A3)였다. Astra 수집은 종료했으며
현재 이 에이전트들에 활성 배정은 없다.

## 재사용할 구현 인계

호패 `cde8416`은 서명 증거 분리, 명시적 시계 속도 계산과 gRPC 디코딩 전 인증을,
품계 `f1ce600`·수문장 `d1e6caf`는 같은 조기 호출자 경계를 구현했다. 전체 workspace는
각각 987/75/131개 통과이며 호패의 기존 제외는 42개다. 수문장은 두 바이너리 이름
검사를 포함한다. 모두 엄격한 전체 대상 Clippy를 통과했다. 런타임 `ed2eee4`는
인스턴스에 결합된 BOOTTIME 교환·집행·보존·경과 표본을 제공하며 24개 검사,
엄격한 Clippy, musl 대상 컴파일을 통과했다. 소비자·원천 절전 적용은 아직 남았다.

[관리자 검토](2026-10-15-admin-ui-review.md)에 세 관점과 ADM-01~09를 정리했다.
이동·변경 안전성·시각 규격의 후속 초안은 저장 전에 중단했으므로 존재한다고
주장하지 않고 원래 검토의 실행 기준을 사용한다. draft 보호·정책 CAS·footer
배치 구현을 진행 중이다. 발견 사항과 프로토타입은 배포된 UI 수정이 아니다.

다음 구현 순서:

1. 구현한 관측 클라이언트 근거를 네이티브 권한·permit·출력·쌍 ledger에 적용한다
   (ADR0018). digest-only 호출자·검증된 동적 신원·프로세스 도메인 부트스트랩을
   해결하고 요청별 채널·외부 원천 pin·가짜 UTC·모드 fallback을 피한다.
2. 실제 소유자·독립 관리 호스트·네 Pod K8s 경로, 회수·재시작·장애, 브라우저 위임,
   정확한 서명 재빌드를 검증한다.
3. 보존한 계획으로 남은 ADM 메뉴·배치·라우팅·다국어·접근성 기준을 이어간다.
4. 자원 예산과 요구 처리량은 별도로 검증한다. unary ingress 소스 적용은 실측
   성능 결과가 아니다.

각 작업은 실제 소스를 다시 확인하고 수용 기준과 커밋·검사 증거를 기록한다.
완료된 검토를 재사용하며 같은 분석을 다시 요청하지 않는다.


리셋 후 Sol 구현 증거: 한강 `b81a310`은 품계 초안과 플러그인 footer·제목 배치를
보호하고 위임 CAS 전달을 검사한다. 전체 workspace·엄격한 Clippy가 통과했고
기존 품계 브라우저 14개·집중 UI 6개도 통과했다. 수문장 `10eab03`은 세대·리비전
정책 문서 CAS와 불확실 결과 편집기 보호를 추가했다. 집중 정책 검사 18개·모의
Chromium 두 모음·플러그인 재생성 검사가 통과했다. 호패 `ce4d27f`는 절전 포함
원천 증명 나이와 초안·성공 응답 보호를 구현했으며 workspace 992개 통과·기존
42개 제외, 엄격한 Clippy·모의 Chromium 35개 통과다. 최초 무제한 병렬 검사는
기존 저장소 예산 타이밍 단언 하나가 실패했으나 단독 및 4스레드 전체 재검사는
통과했다. 시간 제한 단언을 완화하지 않았다. 이는 수정 릴리즈 산출물이나 배포된
K3s 검증이 아니다. 소비자 시계 전환과 공용 ingress 제한은 남아 있다.


후속 구현: 공용 unary ingress를 런타임 `0cdbd166`과 네 컴포넌트(한강 `b41b492`,
품계 `34d74b6`, 수문장 `1f73a18`, 호패 `2a96303`)에 커밋·검증했다. 정확한
증거와 한계는 ADR0017에 기록했다. 호패 선택형 네이티브 클라이언트는 독립 최초
증명 관측·통신별 새 요청 ID·클라이언트별 폐기를 지원한다. Sol 읽기 전용 후속
작업으로 남은 네이티브 소비자 간극을 정리하며 Astra 재검토는 요청하지 않았다.
