# 온톨로지와 보안 자동화

[English](../AUTOMATION.md) · [목차](README.md)

상태: 컴포넌트 선택은 확정된 사용자 요구입니다. 연결 계약과 런타임 어댑터는 설계 단계이며,
Sillok 자체도 개발 중입니다. 실제 자동 대응 파이프라인이 완성됐다는 의미는 아닙니다.

**제로트러스트 온톨로지 엔진은 Sillok입니다.** 리소스·정보등급·사용자·네트워크 자산·취약점·
정책 관계와 변경 이력을 표현합니다. 원래 사실의 권한은 Hangang/Hopae/Guard에 유지하며,
온톨로지에는 발행자·테넌트·관측 시각·만료·근거 해시·원본 리비전을 함께 기록합니다.
추론 결과만으로 인증된 사용자, 활성 라우트나 정보등급 하향을 확정하지 않습니다.

**[Jikji](https://github.com/jikji-labs/jikji)는 자동·반자동화의 핵심 실행 엔진입니다.**
근거 수집, 분석, 변경 제안, 검토, 제한된 실행과 사후 검증을 조율합니다.
Jikji의 기존 온톨로지 도구와 별개로 Sillok을 권위 있는 백엔드로 연결합니다.
Sillok의 현재 제한된 SELECT/ASK와 실험적 형식에 맞춰 버전·기능·작업량을 고정하고,
전체 SPARQL이나 영속 카탈로그/WAL이 완성됐다고 가정하지 않습니다.

## 대응 흐름

펜테스트 도구 → 제한된 근거 정규화 → Sillok 관계·출처 기록 → Jikji 분석·변경 제안 →
범위·권한·리비전 검증 → Guard 정책 / Hangang 라우팅 패치 → 카나리·검증·롤백 → 감사 기록입니다.
영어 문서에는 이 흐름의 Mermaid 도표와 단계별 계약이 있습니다.

스캔은 승인된 테넌트·자산·대상·프로브 종류·기한·동시성·대역폭 내에서 수행합니다.
DNS 재해석과 리다이렉트도 범위를 벗어날 수 없습니다. 도구 출력과 웹 응답은 프롬프트
인젝션을 포함할 수 있는 비신뢰 데이터로 취급합니다. 도구 버전·대상 결합·심각도·신뢰도·
관측/만료 시각·근거 해시를 보존하고, 신뢰도만으로 정책을 변경하지 않습니다.

자동 적용은 운영자가 미리 정의한 대상·필드·영향 한도·만료·검증·롤백 조건을 만족하는
가역적 변경에 한합니다. 나머지는 Jikji의 영속 승인 흐름으로 진행합니다.
승인은 정확한 제안 해시·작업자·범위·기한에 결합하며, 제안 변경 시 다시 평가합니다.
관리 경로·인증 설정·비상 접근은 명시적으로 보호합니다. 도메인 API의 권한 검사와 CAS는
자동/수동 승인 여부에 관계없이 적용합니다. 임의 셸이나 DB 직접 수정 대신 제한된 도구를 사용합니다.

## 실패와 복구

Guard와 Hangang 간 원자적 커밋을 가정하지 않습니다. 변경 조율기는 영속 의도·단계별 결과·
고정 멱등 키를 기록하고, 타임아웃 때 실제 적용 상태를 확인한 뒤 재시도합니다.
재시작해도 완료된 변경을 중복 실행하지 않아야 합니다.
롤백도 현재 리비전을 확인하는 새 CAS 작업입니다. 오래된 전체 설정으로 다른 운영자의
변경을 덮어쓰지 않습니다. 충돌 시 후속 쓰기를 멈추고 정책이 허용하는 안전한 임시 대응을
유지하며 미해결 상태를 표시합니다. 만료에 따른 해제도 권한·리비전을 확인해야 합니다.

온톨로지·LLM·자동화는 제어 경로에 둡니다. Sillok/Jikji 장애가 일반 요청마다 동기 호출을
추가하지 않으며, Hangang은 명시된 유효기간·실패 정책 아래 마지막 검증 스냅샷을 집행합니다.
ClickHouse는 이벤트 조회용이며 정책 권한이나 영속 변경 저널을 대체하지 않습니다.

## 구현·검증 항목

- Sillok 기능/버전 어댑터, 제한된 쿼리와 테넌트·출처 격리.
- Jikji 근거 수집·제안·승인·실행 도구 및 버전별 통합 검증.
- 정규화된 취약점·변경 계약과 Guard/Hangang 제한된 패치 어댑터.
- dry-run, 제한적 자동 적용, 검토 후 적용, 카나리 검증과 롤백 시연.
- 오래된 근거/CAS, 대상 이탈, 프롬프트 인젝션, 중복 작업, 부분 적용,
  재시작 복구, 권한 회수, 롤백 충돌 테스트.
- 자동화·exporter가 일반 요청 성능 예산을 침해하지 않는지 검증.

[피드백 루프](FEEDBACK_LOOP.md)는 로그·분산 트레이스·메트릭·펜테스트 근거를 Sillok으로
연결하고 검증된 대응 결과를 Jikji에서 재사용합니다. 적용 후 제한된 재펜테스트와
정상 트래픽 회귀 확인까지 완료해야 전체 대응 루프가 성립합니다.

## Hearim 판단 백엔드

[Hearim(헤아림)](https://github.com/ziozzang/hearim)을 Jikji가 활용하는 지능·판단
백엔드 중 하나로 선정합니다. 문서화된 `POST /v1/systemone`의 Choice / Score / Noul과
logprob 기반 후보 분포를 판단 보조에 활용하며 다른 백엔드도 함께 사용할 수 있습니다.
실제 어댑터 통합은 구현 예정입니다. Sillok 온톨로지나 Jikji 실행 조율을 대체하지 않습니다.

모델·백엔드·판단 기준 리비전, 입력 근거 해시와 스코어링 진단을 보존하고 입력 최소화·
기한·동시성·테넌트 격리를 적용합니다. 후보 확률과 엔트로피 신뢰도는 보정된 공격 위험도나
정책 적용 권한이 아닙니다. 후보 누락/장애는 판단 불가 또는 검토 대상으로 처리하며
자동 허용으로 바꾸지 않습니다. 실제 변경의 권한·CAS·감사는 독립적으로 검증합니다.
일반 요청마다 추론 의존성을 추가하지 않으며, 재현 가능한 fixture·실패 응답·보정 근거·
개인정보 격리를 검증해야 합니다.
