# 카탈로그와 정보등급

[English](../CATALOG.md) · [목차](README.md)

리소스는 URL과 분리된 안정적인 resource_id, 소유 애플리케이션, 책임 주체와 버전을 가집니다.
Hangang의 route_id와 명시적인 작업(read/write/export 등)이 리소스에 연결됩니다.
분류 엔진은 별도의 경로 정규화 규칙을 만들지 않고 Hangang의 보호 네임스페이스와 일치해야 합니다.

초기 정보등급은 public/internal/confidential/restricted로 제안합니다.
등급은 자동 허용이나 사용자 신뢰 점수가 아닙니다. pii/finance 같은 구획,
테넌트 관계, 권한, 인증 강도와 함께 판단해야 합니다. public도 명시적인 익명 허용 정책이 필요합니다.

클라이언트가 보낸 class 헤더·쿼리·검증 전 JWT·Lua 결과로 등급을 낮추지 않습니다.
보호 리소스의 분류가 없거나 모호하면 public으로 간주하지 않습니다.
정보등급 하향·리소스 제거에는 변경 영향과 승인 근거가 필요합니다.

API 등급은 기본 조건입니다. 문서 소유권·행 ACL·테넌트는 URL만으로 알 수 없으므로
애플리케이션이 실제 메타데이터를 검사해야 합니다. 향후 객체 증명은 발행자·대상·주체·작업·요청·유효기간에
묶인 제한된 계약으로 설계해야 합니다. 임의 응답 헤더를 신뢰 증명으로 쓰지 않습니다.
여러 등급의 데이터가 섞이면 가장 엄격한 조건과 필요한 구획을 유지합니다.

초기 저장은 Hangang 설정 권한과 CAS를 재사용할 수 있습니다. 런타임은 컴파일된 인덱스를 사용하며
매 요청 SQL 조회를 기본으로 두지 않습니다. 롤백도 새 권한 리비전으로 게시합니다.

## API 정의 가져오기

OpenAPI의 x-hangang-resource-id/action/classification 확장으로 카탈로그 제안을 만들 수 있습니다.
크기·참조·경로·확장 타입을 검증하고 임의 외부 참조나 servers 주소로 인증 정보를 보내지 않습니다.
가져온 문서는 라우트나 등급 하향을 자동 게시하지 않으며 소유권·바인딩 검토를 거쳐 활성 카탈로그가 됩니다.
