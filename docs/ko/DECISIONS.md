# 통합 판단 엔진

[English](../DECISIONS.md) · [목차](README.md)

Hopae의 사용자/세션/인증 강도, Guard의 네트워크 결정/위험,
카탈로그의 리소스/작업/테넌트 조건과 활성 정책을 결합합니다.
확인되지 않은 단말 근거를 신뢰 점수에 합산하지 않습니다. 각 근거의 발행자·대상·리비전·유효기간을 검사합니다.

보호 자원의 기본은 거부입니다. 명시적 허용 조건을 모두 충족하고 의무를 실제로 집행할 수 있어야 허용합니다.
결과는 allow/deny/challenge/unavailable로 구분하며 challenge는 부분 허용이 아닙니다.
필수 근거의 최소 유효기간이 허용의 유효기간입니다. 스트림·업로드도 만료나 회수에 맞춰 종료/재검증해야 합니다.

정책은 초기에 제한된 타입 조건과 리소스/작업 범위로 설계합니다.
핵심 신원 처리와 로그인/로그아웃은 네이티브로 지원합니다.
필요한 마스킹·객체 검사 등을 지원하지 않는 구현이 의무를 무시하고 허용하면 안 됩니다.

Guard의 선택적 1–5초 IP 캐시는 전체 사용자/리소스 결정 캐시가 아닙니다.
통합 캐시는 기본 비활성화하고 도입 시 사용자·세션·발행자·테넌트·리소스·작업·정책/카탈로그/신원/네트워크 리비전을
모두 결합해야 합니다. 연결 인증은 미래 요청의 권한을 캐싱하는 뜻이 아닙니다.

서로 다른 DB의 관리 RPC는 하나의 트랜잭션이 아닙니다. 전달 전·응답 공개 전 권한을 재확인하되
이미 수락된 변경의 회수 경합과 결과 불확실성을 기록하고 자동 재시도하지 않습니다.
