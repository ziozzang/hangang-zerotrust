# 관측·온톨로지·펜테스트 피드백 루프

[English](../FEEDBACK_LOOP.md) · [목차](README.md)

상태: 설계 방향은 확정된 사용자 요구이며 어댑터·상관 분석·실행 검증은 구현 예정입니다.
상용 제품과 동일한 구현이 완성됐다는 의미는 아닙니다.

## 전체 흐름

로그·분산 트레이스·메트릭 + 승인된 범위의 펜테스트 → 제한된 정규화·상관 분석 →
Sillok 객체·관계·출처 → Jikji 조사·제안·자동/반자동 실행 → 독립 권한·범위·리비전 검증 →
Guard 대응 / Hangang 라우팅 패치 → 카나리·운영 관측·펜테스트 재검증 →
효과·부작용·불확실성 기록 → 유지·수정·만료·CAS 롤백입니다.
영어 문서에 Mermaid 도표와 상세 계약을 함께 기록했습니다.

펜테스팅은 최초 근거 수집과 적용 후 재검증에 모두 포함합니다.
온톨로지에 자산이 나타났다는 이유로 해당 자산의 스캔 권한을 얻지는 않습니다.
대시보드나 모델 설명만으로 루프가 완료된 것으로 간주하지 않습니다.

## 저장과 의미

ClickHouse에는 로그·트레이스/스팬·이벤트 원본을, Prometheus에는 낮은 cardinality의
지표·SLO를 둡니다. Sillok에는 의미 있는 객체·관계·집계와 원본 참조를 적재하고,
Jikji는 영속 조사·제안·승인·실행 흐름을 관리합니다. 모든 로그를 Sillok에 복제하지 않습니다.
Guard/Hangang/Hopae의 원래 사실과 변경 권한은 각 서비스에 유지합니다.

관측 사실, 추론 가설, 승인 정책, 실제 적용 상태, 검증된 결과를 구분합니다.
테넌트·발행자·관측 구간·원본 리비전·근거 해시·유효기간·필요한 신뢰도를 보존합니다.
모순·근거 부족은 명시하고 만료/철회된 사실이 새 작업을 계속 승인하지 않게 합니다.
추론은 입력 근거의 계보를 유지해 근거 철회 시 관련 제안도 무효화할 수 있어야 합니다.
지표 이상이 곧 공격 증거는 아니며 그래프 관계가 사용자 동일성이나 권한을 증명하지 않습니다.

## 펜테스트 실행과 재검증

작업별 대상 소유권·범위·프로브 종류·자격증명·속도·동시성·기한·실행 주체를 명시합니다.
DNS 재해석과 리다이렉트를 제한하고 관계 그래프를 따라 임의로 스캔 범위를 넓히지 않습니다.
수동 관측, 능동 확인, 서비스에 영향을 줄 수 있는 프로브는 서로 다른 권한 프로필을 갖습니다.
도구 버전·작업 ID·자산/라우트·심각도·신뢰도·재현/근거 참조·시각을 기록하며
스캐너 출력은 프롬프트 인젝션을 포함할 수 있는 비신뢰 입력으로 취급합니다.
취약점 보고서 자체가 정책 쓰기 권한을 갖지는 않습니다.

변경 후에도 승인된 범위와 프로필로 재검증하고 전후 결과·불확실성·검증 공백을 기록합니다.
스캐너 요청이 막혔다는 사실만으로 원래 취약점이 수정됐다고 판단하지 않습니다.
네트워크 임시 격리, 라우트 수준 완화, 애플리케이션 수정을 구분합니다.
재검증 실패가 무제한 공격 프로브 확대로 이어지지 않게 합니다.

## 결과를 다시 활용하는 방식

안정적인 case ID로 관측·취약점·제안 해시·권한/승인·변경 작업·전후 리비전·카나리·
재검증·롤백을 연결합니다. 응답 누락 시 불확실성을 보존하고 실제 상태를 확인한 뒤 재시도합니다.
공격 감소와 함께 정상 요청 가용성·지연·오류·인증/권한 회귀·영향 자산·오탐을 평가합니다.
비교 구간, 샘플링/유실, 기준선 변화와 동시 변경을 기록하고 상관관계를 인과적 성공으로
단정하지 않습니다. 적용 전 수락 기준과 중단 조건을 정해야 합니다.

결과는 다음 Jikji 조사·정책 제안에서 검색할 근거로 재사용합니다.
한 환경의 성공을 곧바로 전역 룰로 확대하지 않고 범위·테넌트·근거 신선도·권한을 다시 검증합니다.
반복된 모델 주장도 관측 사실로 승격하지 않습니다. cooldown·시간당 변경 한도·TTL·
회로 차단으로 스캔과 대응이 서로 증폭되는 루프를 방지합니다.

## 검증과 실패

[자동화 계약](../AUTOMATION.md)의 제한된 실행·영속 의도·CAS 롤백과
[관측 계약](OBSERVABILITY.md)의 개인정보 보호·작업량 제한·유실 계수·비동기 export를 따릅니다.
exporter는 정책을 변경하지 않습니다. Sillok/Jikji/스캐너 장애는 새 자동 작업을 중지하고
불확실성을 표시하며 일반 요청마다 온톨로지·LLM·분석·펜테스트 호출을 추가하지 않습니다.

범위가 제한된 발견, dry-run, 자동/승인 후 적용, 재펜테스트, 정상 트래픽 회귀,
부분 실패/재시작·만료·충돌 안전 롤백을 실제 시연해야 합니다.
테넌트 혼합·대상 이탈·오염된 출력·오래된/철회된 사실·중복 작업·피드백 증폭·
허위 성공 신호를 공격적 검증 항목으로 둡니다.
