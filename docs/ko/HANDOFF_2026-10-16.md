# 구현 인수인계 — 2026-10-16

[English](../HANDOFF_2026-10-16.md) · [설계 목차](README.md)

상태: **사용자 요청으로 일시 중단. 전체 목표는 미완료**.
이 문서는 중단 시점의 기록이며 시험·빌드·배포 재개를 의미하지 않는다.
사용자가 재개하면 저장소·프로세스·바이너리·운영 상태를 다시 확인한다.
이전 readiness 파일만으로 프로세스가 살아 있다고 판단하지 않는다.
배정한 Sol 에이전트는 모두 중단했으며 Astra 사용 금지는 유지한다.

## 목표와 책임

품계 코어/서버 분리, 품계·호패·수문장 고속 독립 서버, 한강 네이티브 집행과
통합 관리자를 완성한다. 호패는 외부·자체·OIDC/Google·LDAP·API·네트워크
인증 혼합, 서비스별 자격 증명 변환, 인증 수명주기와 서킷 브레이킹을 담당한다.
인증된 분산 전송, 권한·정보등급 매트릭스, 장애·회수·성능 검증, 공개 릴리즈와
내부 운영 반영도 목표에 포함한다. 소스/debug 검증만으로 완료 처리하지 않는다.

장부는 로깅·익스포트, 기존 사초는 모니터링, 실록은 온톨로지, 사헌은 감사를
담당한다. 직지 자동화·헤아림 판단·도랑 LLM gateway도 설계에 포함되어 있다.
설계 다이어그램을 실제 구현·연동 완료로 해석하지 않는다.

## 재개 순서

1. 사용자의 재개 지시를 확인한다. Git·프로세스·target 사용권·영구 인수인계
   manifest를 확인하고 필요하면 동결 로컬 소스를 복원한다.
2. 기존 운영 사전 점검 커밋을 검토·게시한다. 실제 운영 바인딩은 비공개로 새로
   수집한다. 이전 manifest는 현재 상태의 증거가 아니다.
3. payload·자격 증명을 기록하지 않는 단계별 계측으로 시험14를 조사한다.
   실제 설정400ms·admission399ms·시계 오차500/500ppm을 유지한다.
   query·증명 수명을 늘리거나 소비한 증거 쌍을 재시도하지 않는다.
4. 실제 전후 소유자 확인, 변경 없는 최초 응답, backend 효과1회, 원래 예산 안의
   보수적 시간 상한을 모두 만족시켜 재사용을 검증한다. 진행 중 logout·정책·IP·route
   회수와 취소 검증도 완료한다. 신규 요청 검증으로 대신하지 않는다.
5. 버전별 정적 바이너리를 정확한 소스·feature와 명시적으로 확보한 target으로
   순차 빌드한다. SDK pin을 보존하고 품계는 `observed-authentication`을 포함한다.
   패키징 도구는 `CARGO_TARGET_DIR` 대신 저장소 `target/<triple>/release`를 읽으므로
   실제 입력 SHA를 확인한다. raw manifest 서명·압축파일·다운로드 바이트를 각각 검증한다.
6. 실제 정적 릴리즈 바이트로 4종·보안 검증을 수행한다. 일관된 백업·shadow 이전·상태를
   포함한 롤백을 검증한 뒤 내부 운영에 반영한다. Human 권한 게시 전 strict reader부터 교체한다.
7. 실제 콘솔과 플러그인 패키지로 ID/PW·SSO·서비스 권한/guest·Human 매트릭스·CAS 실패·
   로그아웃·역할·한영·모바일을 확인하고 기존 트래픽·한강 보안 헤더도 재검증한다.
8. K3s 변경 전 새 백업의 외부 보관·검증과 클러스터 지침 확인을 수행한다.
   기존 workload·스토리지·KMS·route를 보존하며 기능 검증 후 성능을 검증한다.
9. 혼합 provider·복구·서킷 수명주기, 정보등급, DB→인메모리 snapshot/follower,
   멤버십·발견, DBMS/K8s 어댑터와 처리량 측정을 계속한다. 100k QPS는 미입증이다.

## 유지할 경계

- 실제 소유자와 공개 opaque SDK만 사용한다. capability·route reference·digest 기반
  인증 증명 생성 우회를 넣지 않는다.
- Human subject/AAL 계보, 실제 목적지, 최종 method/path/body/header seal,
  class 공통 durable replay ledger를 유지한다.
- 원래 query 나이는 RPC·SQL·응답 준비 뒤에도 유지한다. 취소를 전파하고 commit 뒤
  소비한 증명을 재사용하지 않는다.
- 호패 schema10 롤백은 호환 상태·설정·키 복원이 필요하다. 구버전 바이너리로
  schema10을 열거나 독립 ledger의 동일 realm 운영 복제본을 동시에 띄우지 않는다.
- 상태 seal은 외부 설정·키·환경·이미지·마운트·UID를 포함하지 않는다.
  사전 점검은 filesystem 격리나 자동 전환 제어기가 아니다.
- GitHub Actions 비활성화와 Astra 금지를 유지한다. 다른 프로젝트의 활성 빌드
  target을 정리하거나 관측 timeout만으로 작업을 다시 시작하지 않는다.
