# Hopae와 Hangang 네이티브 인증

[English](../IDENTITY.md) · [목차](README.md)

Google/OIDC의 디스커버리·코드 교환·프로바이더 키·콜백·state/nonce/PKCE,
사용자·세션·인증 정책·step-up·만료·회수는 외부 Hopae 런타임에 유지합니다.
이를 라우팅 프로세스에 복사하지 않습니다.

Hangang에는 네이티브 Hopae 클라이언트, 앱/라우트 바인딩, 신뢰할 수 있는 요청 문맥,
연결 풀과 고속 프로토콜, 로그인/로그아웃 진입점, 안전한 리다이렉트, 쿠키 전달,
신원 헤더 제거/재확정, 세션 회수와 긴 요청의 수명 제어를 넣습니다. Lua를 필수로 요구하지 않습니다.
공통 계약/코덱 라이브러리는 공유할 수 있으나 프로바이더 비밀값은 가져오지 않습니다.

로그인 진입점은 허용된 앱과 복귀 주소에만 연결합니다. 임의 쿼리나 Host로 인증 정보를 보낼 대상을 정하지 않습니다.
Hopae가 실제 외부 인증 흐름과 세션 생성을 수행합니다.
로그아웃은 CSRF/출처·대상 세션 범위를 가진 상태 변경 작업입니다.
쿠키 삭제만으로 외부 프로바이더의 전역 로그아웃이 완료되었다고 주장하지 않습니다.

관리 UI 위임에는 발행자·대상·작업 범위를 제한한 별도 계약이 필요합니다.
Hangang 관리자라고 해서 Hopae의 관리 권한 정책을 자동 우회하지 않습니다.
기존 Hopae 콘솔의 handle/grant/CSRF 계약과 호환성을 먼저 검증합니다.

애플리케이션의 네이티브 로그인/로그아웃과 관리 콘솔 운영자 로그인/로그아웃은 별도입니다.
기존 Hangang 관리 계정 API는 자신의 세션을 소유합니다. Hopae 일반 사용자 세션이 자동으로 Hangang 관리자 권한이 되지 않습니다.

네이티브 진입은 기존 Hopae `/_hopae/login`·`/_hopae/logout` 계약을 사용하고 프로바이더·세션·로그아웃 확인은 Hopae에 유지합니다.
