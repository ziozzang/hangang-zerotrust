# Hopae와 Hangang 네이티브 인증

[English](../IDENTITY.md) · [목차](README.md)

Google/OIDC의 디스커버리·코드 교환·프로바이더 키·콜백·state/nonce/PKCE,
사용자·세션·인증 정책·step-up·만료·회수는 외부 Hopae 런타임에 유지합니다.
이를 라우팅 프로세스에 복사하지 않습니다.

Hangang에는 네이티브 Hopae 클라이언트, 앱/라우트 바인딩, 신뢰할 수 있는 요청 문맥,
연결 풀과 고속 프로토콜, 로그인/로그아웃 진입점, 안전한 리다이렉트, 쿠키 전달,
신원 헤더 제거/재확정, 세션 회수와 긴 요청의 수명 제어를 넣습니다. Lua를 필수로 요구하지 않습니다.
공통 계약/코덱 라이브러리는 공유할 수 있으나 프로바이더 비밀값은 가져오지 않습니다.

로그인 진입점은 허용된 앱과 복귀 주소에만 연결합니다. 임의 쿼리나 Host로 인증 정보를 보낼 대상을 정하지 않습니다.
Hopae가 실제 외부 인증 흐름과 세션 생성을 수행합니다.
로그아웃은 CSRF/출처·대상 세션 범위를 가진 상태 변경 작업입니다.
쿠키 삭제만으로 외부 프로바이더의 전역 로그아웃이 완료되었다고 주장하지 않습니다.

관리 UI 위임에는 발행자·대상·작업 범위를 제한한 별도 계약이 필요합니다.
Hangang 관리자라고 해서 Hopae의 관리 권한 정책을 자동 우회하지 않습니다.
기존 Hopae 콘솔의 handle/grant/CSRF 계약과 호환성을 먼저 검증합니다.

애플리케이션의 네이티브 로그인/로그아웃과 관리 콘솔 운영자 로그인/로그아웃은 별도입니다.
기존 Hangang 관리 계정 API는 자신의 세션을 소유합니다. Hopae 일반 사용자 세션이 자동으로 Hangang 관리자 권한이 되지 않습니다.

네이티브 진입은 기존 Hopae `/_hopae/login`·`/_hopae/logout` 계약을 사용하고 프로바이더·세션·로그아웃 확인은 Hopae에 유지합니다.

## 콘솔 운영자 보증

상태: 브랜치에 구현(Hopae `feat/operator-aal`, ADR-0021, PR #18; Hangang
`feat/operator-aal`, PR #25). 가상 WebAuthn 인증기와 실제 브라우저로 로컬 검증했고,
실제 게이트웨이 검증은 아직입니다.

콘솔 운영자는 피싱에 강한 인증 요소로 Hopae를 통해 로그인합니다. Hopae의
`console_operators` 정책은 콘솔 애플리케이션을 지정하고, 콘솔 호스트 전체에 설정한 수준(기본
AAL 2, 고보증 키가 있으면 AAL 3)과 `webauthn` 요소를, 콘솔의 step-up 경로에는 최근 패스키
사용(`step_up_max_age_secs`)을 요구합니다. 이 규칙은 패스키만 충족·갱신하며 TOTP, 외부 요소,
복구 코드로는 충족되지 않습니다. 패스키가 없는 운영자는 첫 콘솔 접근 전에 패스키를 등록하도록
안내되고, 선택적인 기한부 등록 유예는 패스키가 전혀 없는 운영자만 들여보내며 step-up 경로에는
적용되지 않습니다.

콘솔 애플리케이션의 모든 허용 verify에는 Hopae의 운영자 단언(`x-hopae-operator-assertion`)이
실립니다. 수준, 마지막 2차 요소와 그 시각, 고보증 여부, 정책과 충족 여부를 담고, Hopae 전용
Ed25519 키로 서명하며 60초 동안 유효합니다. 콘솔은 공개 키만 키 ID로 고정하므로(현재 키와
교체 중의 다음 키) 단언을 위조할 수 있는 키를 갖지 않습니다. Hangang 콘솔은 모든 SSO 요청에서 이를 검증하고 자체
최솟값을 적용합니다. 로그인과 읽기는 정책 충족(선택적으로 읽기에 한해 Hopae 유예)을, 모든
변경은 유예 없는 충족을, 민감한 변경(게시, 활성화, 인증 요소 초기화, 계정, 설정)은 콘솔의
`sensitive_max_age_seconds` 안의 인증 요소 사용을 요구합니다. 거부되면 운영자는 게이트웨이를
거쳐 step-up 경로로 가고, Hopae가 패스키 절차를 실행한 뒤 콘솔은 바뀐 세션으로 다시
로그인합니다. 콘솔 헤더는 운영자의 수준과 인증 요소를 보여 줍니다.

Hangang 로컬 관리자 로그인은 비상 경로로 남습니다. 헤더에 그렇게 표시되고, 모든 비상 로그인과
변경은 콘솔 감사에 기록되며, 끌 수 있습니다. 입장은 Hopae가(`operator.console_admitted`),
SSO 로그인·단계 상승 거부·SSO 변경은 콘솔이 운영자의 수준과 인증 요소와 함께 기록합니다.

단언만으로 인증하지 않습니다. 브랜치 콘솔은 고정된 Hopae 채널로 모든 SSO 요청의 네이티브
세션 쿠키를 다시 검증합니다. 서명된 클레임에는 대상 `hangang-console`, 애플리케이션,
호스트, 주체, 세션, 발급·만료 시각이 들어갑니다. 콘솔은 대상·시각을 확인하고 주체와
호스트를 검증 결과 및 설정된 출처와 대조합니다. 일회용 단언이나 요청 nonce를 보장하지
않으며 60초 수명이 재생 범위를 제한할 뿐, 세션 쿠키와 요청별 재검증이 계속 필요합니다.
기한부 등록 유예는 의도적으로 낮은 보증의 읽기 전용 등록 예외입니다. 패스키 정책 충족으로
취급하지 않으며 엄격한 배포에서는 끕니다. 변경·단계 상승에는 적용하지 않습니다.

미결: Hangang 계정 감사 저장소의 영구
콘솔 감사, 하드웨어 인증기를 쓰는 실제 게이트웨이 검증.
