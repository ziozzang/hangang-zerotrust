# 로깅·모니터링·exporter

[English](../OBSERVABILITY.md) · [목차](README.md)

각 런타임의 지표는 Prometheus에서 scrape하고, 검색/분석용 구조화 이벤트는 독립 exporter가
ClickHouse로 배치 전송합니다. ClickHouse는 분석 저장소이며 정책 권한 주체가 아닙니다.
요청별 판정 이벤트 스키마·개인정보 프로필·샘플링·제한된 링/exporter는
[ADR 0019](0019-decision-events-exporter.md)(제안)에 정의합니다.

지표는 결정 결과·지연·장애·풀/큐·회수·유실·재전송·spool/싱크 지연 등을 다룹니다.
사용자 ID·IP·이메일·쿼리를 포함한 URL·세션/요청 ID를 Prometheus label로 넣지 않습니다.
이벤트도 허용된 최소 필드만 담고 헤더/본문/프로바이더 토큰을 통째로 저장하지 않습니다.
가명화와 익명화를 같은 것으로 취급하지 않으며 필요한 상관 범위·키 회전·보존·접근 권한을 설계합니다.

일반 요청은 원자적 카운터와 제한된 큐만 갱신하며 분석 DB 쓰기를 기다리지 않습니다.
일상 이벤트는 명시적인 샘플링/유실 정책과 카운터를 갖습니다. 공격자의 거부 폭주가 무제한 저장으로 이어지면 안 됩니다.

중요 관리자 감사는 별도 제한된 로컬 영속 journal에 변경 수락 전에 기록합니다.
필수 감사 공간이 없으면 해당 변경을 전달하기 전에 거부합니다. ClickHouse 장애 자체가 모든 요청을 멈추게 하지는 않습니다.

영속 재전송은 at-least-once이며 안정적인 event_id와 중복 제거 조회가 필요합니다.
ClickHouse의 merge나 retry가 exactly-once를 보장한다고 주장하지 않습니다.
비동기 INSERT에서도 wait_for_async_insert=1 등 저장 확인을 요구하고 큐·배치·재시도·spool에 한도를 둡니다.
콘솔은 권한과 조회 범위가 제한된 API를 사용하며 ClickHouse 비밀값이나 임의 SQL을 브라우저에 주지 않습니다.

로깅·분산 트레이싱·모니터링은 [온톨로지·펜테스트 피드백 루프](FEEDBACK_LOOP.md)로 연결합니다.
Sillok에는 의미 있는 사실과 출처 참조를, Jikji에는 조사·제안·실행 결과를 연결합니다.
대응 전후 펜테스트와 정상 트래픽 영향을 함께 검증하며 원본 분석 저장소 및 정책 권한은 분리합니다.
