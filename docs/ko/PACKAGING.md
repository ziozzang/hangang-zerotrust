# 구성요소 이미지 패키징

[English](../PACKAGING.md)

`tools/package_component.py`는 미리 기능 검증한 한강·호패·수문장·품계의 정적 ELF
파일을 패키징합니다. 먼저 선택한 소스 리비전을 빌드·검증해야 합니다. 전체 Git
리비전을 요구하고 동적 로더 파일은 거부합니다. 실행 파일과 Dockerfile만 있는
비공개 임시 디렉토리에서 빌드하며 설정·DB·공급자 자격·TLS 파일은 배포 때 따로
제공합니다. 소스 트리를 이미지에 복사하지 않습니다.

scratch와 UID/GID 65532를 사용합니다. 읽기 전용·네트워크 없음·capability 없음·
no-new-privileges 조건에서 --version 시작을 확인하고 이미지 ID와 크기를 보고합니다.
소스 라벨은 호출자가 선언한 리비전이며 암호학적 출처 증명이나 소스와 바이너리의
일치 증명은 아닙니다. 버전 시작 검사도 기능 검증을 대신하지 않습니다.

```sh
python3 tools/package_component.py --component hangang --binary /qualified/hangang --revision 0125779c1f807330544c466e8450aee10c7195ee
```

로컬 이미지 생성은 레지스트리 게시·서명 릴리즈·Pod 배포·K8s 원천 어댑터·한강 월드
통합 패키지의 완료가 아닙니다. 실제 클러스터에서 네 독립 서비스·mTLS Service DNS·
요청 집행·관리자 위임·영속/재시작·장애 거부를 검증해야 합니다.

## 품계 0.1.4 검증 — 2026-10-15

서명 정적 소스 `89e5987cfee934f2fb6b9f007064bc6525999715`의 재다운로드 자산을
독립 검증하고 `hangang-world/pumgye:89e5987cfee9`로 패키징했습니다. 아카이브
체크섬 일치 후 원격 K3s 두 노드에 가져왔습니다. 한강 0.3.4·호패 0.0.6·수문장
0.3.4와 실제 네 서버 검사에서 브라우저/모듈 위임·자원 메타데이터 CAS·즉시/영속
회수·Pod 교체·장애·거부 시 백엔드 미전달이 통과했습니다. 기존 백업/오프호스트
사본·DNS·노드 Ready·HTTPS 서비스를 보존했습니다.

실제 한강 클라이언트의 호패 서비스 receipt 검증도 통과했습니다. 품계 permit RPC
활성화·분산 receipt 소유자 신선도·K8s의 새 선택적 영속 신뢰 자원 검증은 별도입니다.
새 키/범위 하한은 로컬 55개 검사·정적 mTLS 검사로 검증했고 내부 품계 0.1.4는
DB 복제본 사전 검사·재시작과 함께 배포했습니다. 잘못된 digest 참조는 이제
클러스터 작업 전에 거부합니다.

## 서명 네이티브 관측 릴리스·내부 적용 — 2026-10-15

품계 0.1.5·호패 0.0.7·수문장 0.3.5의 Linux amd64 정적 musl 자산을 게시했습니다.
정확한 새 버전 세 권위 endpoint 검사를 통과하고 재다운로드한 모든 자산의 원본
일치·고정 서명·버전/대상/URL 바인딩을 확인했습니다.

내부 적용은 실제 DB/설정 사전 검사·비공개 일관된 백업·정책/보호 신원 데이터 유지·
네이티브 mTLS 거부·재시작을 통과했습니다. 수문장 감독 worker 인계도 통과하고
기존 observe 모드를 유지합니다. 세 실행 버전을 확인했고 한강 관리자 HTTPS는
200을 반환합니다. 기존 환경의 발급자/신뢰/실시간 자원은 미설정이므로 이번 적용으로
새 receipt 기반 판정 경로나 권한을 활성화하지 않았습니다. 실제 경로는 격리된
정적 프로세스에서만 검증했습니다.

K8s 통합 endpoint·한강 요청 전달·서명 permit/라우팅/투영 소유자·분산/복구 하한과
전체 목표 완성은 남아 있습니다. 기존 서명 자산은 변경하지 않았고 Actions도
활성화하지 않았습니다.

## 네이티브 관측 K8s endpoint — 2026-10-15

정확한 서명 한강 0.3.4·품계 0.1.5·호패 0.0.7·수문장 0.3.5 자산의 격리 네 서버
검사가 통과했습니다. 새 --authenticated-client 옵션은 receipt 발급·자원 카탈로그
검사를 요구하고 품계에 명시적 공개 신뢰/mTLS 자원을 주입합니다. 실제 Pod에서
호패 실시간 receipt·수문장 Enforce 질의를 mTLS Service DNS로 결합한 자원 Allow를
확인했습니다. 로컬 정적 클라이언트는 품계 mTLS HTTPS 응답도 검증합니다.

기존 실제 브라우저/모듈 위임·정책/카탈로그 CAS·일반 요청 회수/복구·Pod 교체·
장애 시 백엔드 미전달·로그아웃도 통과했습니다. 테스트 네임스페이스는 제거하고
합성 Retain PV는 보존했습니다. 새 콜드 백업의 archive 무결성을 테스트 전에
확인하고 클러스터/인증 컨테이너 복구·기존 DNS/Ingress를 검사했습니다. 원래
오프호스트 전송도 이후 완료돼 전체 SHA-256이 완전한 원격 원본과 일치했습니다.
두 비공개 완전 백업을 유지하며 실패한 보조 구간 전송은 근거로 사용하지 않았습니다.

새 K8s endpoint 단계는 통합 정상 허용만 증명합니다. receipt 회수/장애는 로컬 정적
세 권위에서 검증했으며 이 K8s endpoint에서는 반복하지 않았습니다. 한강 운영 전달·
서명 permit/투영·분산/복구 경계는 남아 있고 기존 원격 운영 서비스를 유지했습니다.
