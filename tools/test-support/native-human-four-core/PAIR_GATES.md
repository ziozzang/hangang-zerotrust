# Actual native Human lineage and exact-pair gates

These opt-in local candidate gates extend the actual four-core supervisor without changing the historical first-positive/fresh-request results. They use the same real native accounts, shared Hop Source, Pum policy/native observers, Sum, Root request capture and canonical Hop paired ledger. They create no signatures, route references, opaque observations or production capability constructors.

Select exactly one `--pair-gate lineage` or `--pair-gate replay`, with the normal exact artifact manifest/observer/tap interpreter arguments and explicit `--gateway-proto` / `--decision-proto`. Fresh MFA gates cannot be combined in the same invocation. Both accounts log in directly against the actual Hop portal before the tap starts; no Source restart or configuration change is used to obtain account B's private cookie. Public SDK Issue plus independent Observe obtains both canonical subjects, then actual Pum management grants both.

The hook parser explicitly pins the full PUBLIC b08 gateway snapshot (`b08e105666de99f2ae957cff16ca9f3c75d3f7c5`, `crates/hopae-grpc/proto/gateway.proto`, SHA745a367111a0e9cb963dca8461841dd26bdbdea4cefafb502f9a5096f21c388c) and Pum f6 decision snapshot (SHA df2ed98f9c9b5df451874f93ab91b11d2e83b4583f4618613f40729db3e4539b). The actual native Hop/SDK remains public e1dd. The only b08→e1dd gateway proto difference is the additive six-line Human projection service; all message definitions are byte-identical. This parser provenance is distinct from native SDK trust. Do not relabel an e1dd file as the old pin, strip a service to fabricate a snapshot, or interpret parser DTOs as authentication capabilities.

In lineage mode, the tap begins explicitly unarmed. Same-fixture A/A and B/B requests must both return204 and cause exactly one backend arrival/effect with matching body/credential and stripped identity. A private one-way arm IPC affects future RPC entries only. The next fresh A request keeps ordinary Verify/typed policy as A, while the actual Source Issue verification cookie alone becomes the real B cookie. Both accounts are granted. The gate requires actual Verify, Human preliminary Decide and Source Issue to succeed; Root must then return503 with backend0, Pum Issue delta0 and Project delta0. This demonstrates the actual preliminary/final canonical subject comparison rather than a policy denial confound. It does not recall prior Lua side effects.

Replay mode also starts unarmed with an actual positive control. After arm, a new real Root request issues a fresh actual auth/permit pair. Inside the tap, after the real Hop first Project succeeds and before returning its unchanged reply to Root, the hook calls actual Pum Observe, replays the exact original raw Project bytes/ID, then calls actual Pum Observe again. The real Root capture remains owned throughout. The replay must return the fixed native Human projection refusal, both original permit observations must remain valid and monotonic, and the unchanged first reply must yield exactly one actual backend effect. No channel restart, credential replacement, source refresh or deadline extension is used.

A refusal status alone is not sufficient evidence of ledger rejection. The runner also reads the actual Hop startup config: gateway verify budget is explicitly400ms, equal to the native default; the Human transport caps at1000 and Owner.admit subtracts1, yielding the original399ms limit. Its SHA is recorded immediately before the actual process spawn and must match the bytes read for the gate. The hook's CLOCK_BOOTTIME interval begins before the FIRST Project call and ends after the replay call completes. With actual configured rates500/500, the runner charges `ceil(ns*(1000000+500)/((1000000-500)*1000000))+2` milliseconds and requires this strict upper bound to be **less than399**. The two extra milliseconds conservatively charge native tick endpoint quantization plus the native remaining-at extra subtraction. Near-boundary, wrong-type, changed-config or unknown-budget evidence fails/inconclusive; a proof TTL or caller-supplied budget never substitutes for the original query. Exact native ledger unit/rollback tests complement this external status observation; no distributed atomic or exhaustive cause claim is made.

Output contains only safe statuses, exact counter deltas, hashes, scope/AAL metadata, elapsed durations and cleanup facts. Cookies/proofs/secret header values remain private and absent from result JSON. These gates do not establish in-flight withdrawal, alternate provider coverage, operating activation or throughput. Actual execution results are recorded separately from pure oracle/control tests.
